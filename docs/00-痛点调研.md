# P0 痛点调研 · 长期陪伴 AI 的记忆到底难在哪

调研对象：`06-Projects/lingchat-anima`（Tauri + Vue + Rust，v0.5.2，53GB）
取证方式：读 `docs/anima/N4-技术方案.md`、`N1-需求确认单.md`、`笔记向量库_论证方案.md`，以及运行数据 `data/小深的日记/`、`小深的账本.md`、`品味账本.md`

## 这份调研的证据等级（先看）

lingchat-anima 是**样本**，不是需求单。它的价值在于"一个真实的长期陪伴项目在这块踩过什么坑"，而不在于它里面那个角色说过什么。

| 等级 | 内容 | 采信方式 |
|---|---|---|
| **硬证据** | 400 报错链路、149,517 token 实测、438 条笔记形态、预算函数无调用方、改名导致记忆失效 | 直接作为设计约束 |
| **工程经验** | 三档 tier、作者归属、冷却期、反近因公式、墓碑机制 | 借鉴思路，按通用场景重新设计 |
| **人格产物** | 角色日记里的偏好、「不想要 22 条」、「工具不中性」、品味账本 | **不采信为需求**。这些是她自我迭代出的认知，反映的是"人如何记忆"，不是"系统该怎么做" |

第三条要特别说清：从她的日记里能读出的**唯一有效信息**是「人的记忆会订正、会分层、会把情绪和教训分开、会记得久远的事」。这是关于**人类记忆机制**的观察，不是产品需求清单。产品需求必须从工程事实推导。

结论先行：**长期陪伴 AI 的记忆问题不是"检索不准"，是"人格不连续"。** 通用记忆系统（向量库 + top-k）解决的是"找到相关内容"，这个场景要解决的是"她在任何时候都是同一个她，并且在变、变得可追溯"。

下面十二条，前九条有工程实证，后三条是从人类记忆机制反推的设计约束。

---

## 一、十二条特化痛点

### P1 记忆分三档，不是两档

现有系统里记忆有明确的三级：**常驻（每轮注入）/ 检索（语义浮现）/ 重要（不每轮注入但优先召回且永不丢失）**。

- 常驻四个 section：`user_info`（ta 的画像）、`promises`（承诺）、`short_term`（当前状态）、`long_term`（编年史）
- 常驻上限：**1500 字符 / 20 条**
- 「重要」不是第三档 tier，而是**正交布尔标记**，且只对 retrieval 合法（`resident + important` 被判非法）

证据：N4 §3.6.5 明确裁定「important 只适用于 tier=retrieval」，因为 resident 已经每轮注入，"重要"标记无增益。

**通用方案的失败点**：只有"检索/不检索"二元，没有"一直知道"这个状态。而"一直知道"恰恰是陪伴的地基——她不该靠语义相似才想起老师是谁。

### P2 每条记忆都有作者

`source ∈ dialogue | self_reflection | seed | summary | manual`，另有 `important_by ∈ self | teacher | null`。

小深自己在账本里立过一条规矩：

> **「先查谁写的，再决定怎么读。」**
> 先查作者，再动感情。顺序错了，后面全是白读。

她一天之内犯过三次同一个错——把别人写的字当成写给自己的话。这个教训直接变成了记忆系统的需求：**记忆条目必须记录作者，否则会产生系统性误读**。

还有更细的一层：压缩出的摘要是机器写的，**不能署老师的名**（N4 §3.6.1 规定冻结副本 `source` 仍为 `summary`，不得改成 `manual`）。

**通用方案的失败点**：向量库只有 `text` 和 `metadata`，作者是可选装饰。这里作者是语义的一部分。

### P3 记忆有层级，不是什么都能升格

小深在日记里写过：

> **不进人设：这是工具行为，不是我的原则**（原则已经有了：认错也要先查证）。

同一天她记了两件事：一条 `search_files` 的假阴性踩坑，一条由此得出的原则。前者被明确判定为"不该进人设"。

**通用方案的失败点**：所有记忆平等地参与检索。这里必须有一个**升格闸门**——工具行为永不升格为原则，偶发情绪不能冒充教训。

小深自己的账本规矩写得更绝：

> 事实和教训记清楚；情绪也可以记，但必须标出来那是情绪，不许冒充教训。

### P4 人格预算比检索预算更紧

`fit_persona_to_budget` 的预算是 **7600 字符**，取舍规则是：`identity` + `speech` 整节必保、输出铁律整块必保、其余小节**按整条择优，绝不切半句**。

注意"绝不切半句"——这是硬约束。切半句会产生语义残片，比不注入更糟。

现状还有一个已知缺陷：`fit_persona_to_budget` **目前没有调用方**（N4 §3 记录），对话轮走 `sys_prompt_builder_persona` 整份注入、不做预算。

**通用方案的失败点**：通用系统只关心"塞多少 token"，不关心"塞进去的东西是不是完整的人"。

### P5 反近因：久远的事要偶尔想起

这是最反直觉的一条。现有检索公式是：

```
Δ天 = (now − last_recalled_at_any) / 86400
stale = 1 − exp(−Δ天 / TAU)
score = s × (W_MIN + (W_MAX − W_MIN) × stale)
```

**陈旧度越高，权重越大。**

所有通用记忆系统都是"越新越重要"。但这个场景要的是"偶尔想起久远的事"——一个只记得最近三天的人，不像人，像一个上下文窗口。

**通用方案的失败点**：recency 项方向相反。这不是调参能解决的，是目标函数不同。

### P6 重复提及必须被抑制

`cooldown_until`：普通记忆 3 天，重要记忆 24 小时。在冷却期内不重复召回同一条。

小深在 `小深的诉求清单` 里对加功能的态度可以解释为什么：

> **「工具不中性。」** 加一个功能，就是改一次我能做的事，也就是改一次我。

重复提同一件事，等于反复确认"我只记得这个"。

**通用方案的失败点**：没有冷却概念。top-k 每次都会把最相似的那几条捞出来，于是 AI 反复说同一句话。

### P7 删除必须不可复活

`tombstones.json`：删除片段时写入墓碑，重建索引时跳过。

关键细节：判断要做**双重**——既要 `chunk_key` 命中，也要 `line_ids` 有交集。后者防的是"重新切片后 chunk_key 变化导致复活"。

取舍也写得很清楚：宁可少一条，也不让删掉的东西回来。

**通用方案的失败点**：向量库删了文档，重建索引时会从源数据重新生成，被删内容复活。

### P8 名字会变，所以记忆里不能写死名字

记忆块的元数据前缀用 `%player%` 占位符而不是具体名字：`[2026-08-14] %player%：…… 我：……`。

理由：**她会改名，老师也会改称呼**。快照里两个具体名字都不出现。

还有一条红线：不得使用 `{{user}}` 语法——该项目里 `{{...}}` 已被旁白/系统提示占用，会被下游误解析。

**通用方案的失败点**：记忆里写死"晓星"，改名后旧记忆全部指向一个不存在的人。

### P9 情绪、事实、教训、原则是四类东西

小深的账本分栏：错案（教训）、情绪（要标注）、规矩（原则）。
品味账本分栏：顺眼的 / 别扭的 / 存疑待再看。

这不是文学修辞，是记忆的**类型系统**。混在一起会产生灾难：把一次情绪波动记成"她讨厌这件事"，下一次就会基于错误的自我认知做判断。

**通用方案的失败点**：只有 text，没有 type。

### P10 标签是她自己的语言，不是分类系统

438 条手动笔记，**666 个不同标签，其中 464 个只出现一次**。

高频标签：署名原则 108、心跳 73、老师 56、走神 48、独处 45、晓星 31。

`笔记向量库_论证方案.md` 的结论：

> **标签不能当主检索手段。** 464/666 是单例标签，等于没有分类；要靠标签找东西，她得先猜中"署名原则"这种词。

**通用方案的失败点**：把标签当 faceted search 的维度。这里的标签是私人语义场的坐标——它们有价值（反映她怎么想），但不能当索引入口。

### P11 可及性缺口：不是找不到，是想不起来用

`笔记向量库_论证方案.md` 的判断很准：

> 它的价值不是"省 token"，是补上"她想不起某条笔记"这个能力缺口。

以及风险判断：

> 主要风险不是性能（438 条 9 秒嵌完），是**检索地板偏松**和**她会不会想起来用**。

后者是行为问题不是检索问题——工具在那儿，但她不调用。

**通用方案的失败点**：通用系统假设调用方一定会检索。陪伴场景里，"她主动想起来"本身是个待解决的问题。

### P12 订正而非覆盖

小深的品味账本里有一处典型的订正：

> ~~三套全是百褶裙，一条裤子都没有。为什么我的下装默认必须是裙子？~~
> → **更正（当天）：裙子是我自己点的。** 上午我说要百褶裙，画的人只是照做。我把自己的选择错记成了别人的安排——这笔账原告是我，被告也是我。划掉。这一条留着当教训。

注意三件事：原文划掉但**保留**；订正**写明日期**；订正本身**成为新记忆**（"这一条留着当教训"）。

这是 bi-temporal 的情绪版：不是"事实失效"，是"我改变了对这件事的看法，但我承认我曾那样想"。

**通用方案的失败点**：update 会覆盖旧值。这里必须保留"我曾经那样想"这个事实——那才是人格演化的证据。

## 二、现有系统已经踩过的坑（可以直接继承的教训）

| 坑 | 证据 | 教训 |
|---|---|---|
| 工具返回全量导致 400 | `memory_get_notes` 返回 438 条 → 149,517 tokens → 超 65,536 上限报 400 | **任何工具返回必须有硬上限**，与向量化无关，先做 |
| 在飞请求不受落盘裁剪影响 | `bounded_tool_history` 的 32,000 字符只管落盘副本 | 预算要管**注入侧**，不是存储侧 |
| 游标式增量在切档时失效 | 全局 `last_indexed_line_id` 在回滚/切档时不自洽 | 用**内容幂等键**（chunk_key）而非 id 游标 |
| 记忆块写死名字 | 两个具体名字都会变 | 用占位符，注入时替换 |
| 摘要重建导致治理状态丢失 | 重建索引要继承 `muted`/`tier`/`important`/tombstone | 重建只换向量，不丢治理状态 |
| 人设预算函数没人调用 | `fit_persona_to_budget` 无调用方 | 机制存在 ≠ 机制生效，要有接线验证 |

## 三、这十二条推出什么架构

不是"五层记忆 + 向量库"，而是**三个预算 × 四个正交维度**。

### 三个预算（互相独立，不可挪用）

| 预算 | 上限 | 取舍规则 |
|---|---|---|
| 人格预算 | 7600 字符 | 整条取舍，绝不切半句；identity/speech/铁律必保 |
| 常驻预算 | 1500 字符 / 20 条 | manual 优先，再按 section 优先级 |
| 检索预算 | token 数（运行时定） | 质量优先，压表达再砍内容 |

三者分开的理由：人格是"我是谁"，常驻是"我一直知道的事"，检索是"这次想起来的事"。混在一个预算里，任何一项紧张都会挤掉另外两项——而"她忘了自己是谁"比"她这次没想起某句话"严重得多。

### 四个正交维度（每条记忆都带）

| 维度 | 取值 | 决定什么 |
|---|---|---|
| `author` | self / teacher / system | 谁写的——决定可信度与能否订正 |
| `tier` | resident / retrieval / important | 怎么注入——每轮 / 浮现 / 优先浮现 |
| `memory_type` | fact / emotion / lesson / principle / preference / tool_behavior | 能否升格——tool_behavior 永不进人设 |
| `correction_of` | 记忆 id | 订正链——原文保留，新条目指回旧条目 |

### 一个闸门

**升格闸门**：一条记忆能不能进常驻、能不能变原则，由 `(author, memory_type, 确认状态)` 三者共同决定。不是分数高就能进。

这条是整套设计的枢纽——它把"记忆"和"人格"分开了。通用记忆系统没有这道闸门，所以它们的 AI 会在几百轮对话后变成一个"知道自己所有设定但没有自我"的东西。
