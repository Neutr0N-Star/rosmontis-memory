# N1 需求确认单 · Rosmontis

项目：长期陪伴 AI 的专用记忆系统
日期：2026-10-18
工作室：Sext 晷刻（通用实用软件）
形态判定：**纯后端 / CLI** → 走捷径路径 `N1→N2→N4→G1→N5b→G2→N6→G3→N7`，跳过 N3 设计簇

## 一句话目标

为长期陪伴 AI 造一个独立的记忆器官，替换「分层记忆 + 向量库」的简单模式，使其能应对语义扩散、召回二值性、无时间动力学这三类结构性缺陷。

## CEO 拍板记录

| 议题 | 决策 |
|---|---|
| 交付形态 | 做成尽可能完善的样态，可以是完整服务；不做合规审查与对外发放准备；不考虑笨重，50GB 磁盘预算内 |
| 模型成本 | 由方案论证决定；本地够用就本地，不够用云 |

## 需求拆解（四条硬约束）

**R1 语义扩散必须被约束。**
向量检索会把语义相近但主题无关的内容拉进来。要求：召回结果必须与当前对话主体在图上有连通性，或落在时间窗内；同一批结果内不得出现语义重复。

**R2 召回必须是连续量，不是二值量。**
top-k 硬截断导致边界跳变——要么全中要么全不中。要求：按 token 预算贪心填充，分数连续排序；设明确的三级分带（必须/优先/补位）；最高分低于阈值时明确拒答，而不是硬凑。

**R3 必须有时间动力学。**
长期陪伴的核心是"人变了"。要求：事实带双时间（世界时间 + 系统时间）；旧事实失效但留痕；显式维护当前状态快照；重要度随召回强化、随时间衰减。

**R4 可独立部署、可被任何项目调用。**
不绑定特定前端或后端框架。要求：零第三方依赖（标准库 + SQLite + HTTP），单文件数据库，进程内库 + HTTP 服务双形态。

## 非目标（明确不做）

- 不做多租户 SaaS、不做权限体系
- 不做模型微调、不做参数化记忆（Memory Layers / LoRA 路线已论证为 2026 年不具备经济性）
- 不做 GraphRAG 全量社区摘要（成本 100-1000 倍，收益仅在全局性问题）
- 不做合规审查、不做对外发放打包
- 不替代对话模型本身，只做记忆层

## 验收口径

1. 九类机制测试全绿，覆盖 R1-R4 每条要求
2. 一个能亲眼看见记忆被写入/更新/失效/遗忘的可视化界面
3. 一个可交互命令行，能完成写入、检索、时间旅行、遗忘、体检
4. 技术方案与代码一致，无「文档写了没实现」的项

## 风险登记

| 风险 | 应对 |
|---|---|
| 本地 2B 模型抽取质量不足 | 设计 LLM 分层：热路径本地、关键判断可切云端；规则抽取做兜底，LLM 不可用时不崩 |
| SQLite 向量检索全表扫描慢 | 分段量化 + 分块桶索引；十万级记忆内可接受，超过走 ANN 外挂接口预留 |
| 中文分词 | 不引入 jieba 依赖，用字符 n-gram + 停用词表实现 FTS5 检索 |
| 过度设计导致跑不起来 | G1 评审门硬性要求：每个抽象必须有可运行的最小实现，禁止只写接口不写实现 |
