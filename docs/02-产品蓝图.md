# N2 产品蓝图 · 藏识 Rosmontis

## 产品定位

一句话：**给 AI 装一个会遗忘、会改主意、会记得"你以前不是这样"的记忆器官。**

不是在向量库前面加一层，而是换掉记忆的**存在形式**——从「一堆等距的文本片段」换成「一个有状态、有时间、有主体、有置信度的世界模型」。

## 为什么现有方案必败

现有的「分层记忆 + 向量库」本质是：

```
用户说了什么 → 切块 → 向量化 → 存起来
要回答时   → 把问题向量化 → 找最像的几条 → 塞进上下文
```

这个结构里有三个隐含假设，全部是错的：

| 隐含假设 | 为什么错 | 后果 |
|---|---|---|
| 记忆是**一堆平等的片段** | 记忆有层级：状态 > 事实 > 情节 > 原文 | 三个月前的重要事实和昨天的一句闲聊同权竞争 |
| 相关性 = **语义相似** | 相似 ≠ 相关 ≠ 该用 | 语义扩散：聊猫的时候把「怕黑」翻出来，因为都涉及"恐惧" |
| 记忆是**只增不改**的 | 人会变，旧事实必须失效 | AI 记得你上一份工作，因为你从没"删除"过它 |

## 概念模型：五层 × 三轴

### 五层（存在形式）

```
State   当前世界快照     ← 读的时候永远先看这层
  ↑ 由 Fact 推导
Theme   主题超边（n 元）  ← 跨月的经历归组
  ↑ 由 Episode 归纳
Fact    结构化断言 + 双时间
  ↑ 由 Episode 抽取
Entity  人物/地点/物件画像
  ↑ 由 Fact 聚合
Episode 原始事件（不可变）  ← 一切可回溯到这里
```

关键点：**上层是下层的投影，不是下层的替代。** 上面任何一层出错，都能顺着链回到原文核对。这解决了"摘要越省 token 丢得越多且无法追溯"的问题。

### 三轴（怎么用）

- **时间轴**：每个事实有两个时间——世界时间（这事什么时候为真）和系统时间（系统什么时候知道 / 什么时候判定它失效）。两者分开，才能回答"他现在住哪"和"我当时以为他住哪"。
- **重要度轴**：创建时打分，被召回时强化，长期不被召回则衰减。重要度高的事衰减更慢——这是"刻骨铭心"的工程版本。
- **置信度轴**：用户亲口说的 > 用户暗示的 > AI 推测的。冲突时按置信度投票，而不是按谁更新。

## 六项能力

### 1. 写入（Write）
一条消息进来，走完整状态转移：切事件 → 抽实体事实 → 冲突消解（新增/更新/作废/忽略）→ 超边归组 → 状态快照更新 → 重要度打分。

不是 append，是**事务**。

### 2. 检索（Recall）
四阶段：理解问题 → 三路召回（语义/关键词/图游走）→ 连续重排 → 预算内组装。

返回的不是一段文本，是**带出处的结构化证据**：哪条事实、来自哪句话、什么时候、有多确定。

### 3. 时间旅行（As-of）
任何一次检索都能指定「站在哪个时刻看」。可以问：
- 他现在的工作是什么（现在）
- 三个月前他以为自己的工作是什么（当时）
- 这条关于"搬家"的记忆是什么时候被推翻的

### 4. 遗忘（Forget）
三级：降权 → 折叠（多条同主题情节合并成摘要，原文保留）→ 归档（移出热区，仍可显式查询）。

**永不物理删除。** 遗忘是降低可及性，不是消灭。

### 5. 体检（Audit）
报告记忆库的健康状况：多少条事实互相矛盾、多少条超过半年没被召回、哪些实体只有名字没有画像、哪些主题下面积压了过多未折叠的情节。

### 6. 可视化（Inspect）
一个网页，能看见：记忆分层结构、实体关系、事实时间线、检索打分明细（为什么这条被选中、那条被排除）。

**这是验收的关键**——不用读代码也能判断它对不对。

## 用户使用路径

```
写：POST /v1/episodes            → 存一句话，返回这次写入做了什么（新增几条事实、作废几条）
问：POST /v1/recall              → 问一个问题，拿回证据包 + 打分明细
看：GET  /v1/timeline/{entity}   → 某个人的事实变更史
改：POST /v1/forget              → 手动触发遗忘/折叠
查：GET  /v1/audit               → 健康报告
看：GET  /                        → 可视化界面
```

## 与现有方案的正面对比

| 维度 | 分层+向量库 | 藏识 |
|---|---|---|
| 记忆单元 | 文本块 | 事件 / 事实 / 实体 / 主题 / 状态，五种粒度 |
| 检索 | 一次余弦 top-k | 三路召回 + 连续重排 + 预算组装 |
| 时间 | 一个 created_at | 双时间轴 + 状态快照 + 时间旅行 |
| 事实变化 | 再存一条，新旧并存 | 旧条作废但留痕，状态表更新 |
| 遗忘 | TTL 或不管 | 衰减 → 折叠 → 归档，三级且可逆 |
| 失败表现 | 自信地答错 | 明确拒答，且能说清"我为什么没记住" |
| 可解释 | 一个相似度分数 | 四个分项 + 排除理由 |

## 第一性目标：帕累托边界上的记忆

记忆系统真正的优化目标不是「记得多」，也不是「记得准」，而是：

> **在固定 token 预算下，最大化这一轮对话用得上且用得对的信息量。**

这是一个带约束的优化问题，三个变量互相拉扯：记忆质量 ↑ 通常要更多 token；token ↓ 通常牺牲质量。所谓帕累托平衡，就是找到那条边界——**在同等 token 下质量最高，或在同等质量下 token 最省**。

### 渐进式注入（Progressive Disclosure）

核心机制：同一条记忆按四个粒度存放与呈现，检索时**从最省的那一级开始**，只有前面不够用时才升级。

| 级别 | 形式 | 约 token | 用在什么时候 |
|---|---|---|---|
| L0 指针 | `[工作:字节跳动]` | 6-10 | 只需要"知道有这回事" |
| L1 三元组 | `用户 工作在 字节跳动（自 2026-07）` | 18-24 | 需要事实内容 |
| L2 摘要 | `三个月前从上一家公司跳到字节做后端` | 35-50 | 需要来龙去脉 |
| L3 原文 | 用户当时说的整句话 | 80-200 | 需要精确复述或引用 |

**为什么这是关键**：现有方案无论问题多简单都塞整段原文。渐进式注入让"今天天气怎样"这种问题只花 10 token，"我们第一次聊到猫是什么时候"才升级到原文。同等预算下能装下的记忆条数提升 3-5 倍。

### 预算分配（默认，可调）

| 层 | 配额 | 理由 |
|---|---|---|
| State 快照 | 15% | 最贵但最值——它决定 AI 会不会认错人 |
| Fact 结构化 | 40% | 性价比最高的一层 |
| Episode（渐进式） | 35% | 情感细节与精确复述 |
| Theme 主题 | 10% | 跨会话的背景感 |

分配是**软上限**：某一层用不完的配额会让给其他层，但 State 层不满时不占用它的额度（因为漏掉状态是灾难性错误，不是边际损失）。

### 边际收益贪心

每条候选记忆计算 `价值 / token 成本`，按性价比排序填充，而不是按分数排序。一条 200 token 的原文如果只比 20 token 的三元组多 10% 价值，就不该选它。

价值 = 重排分数 × 层级权重 × (1 - 与已选项的冗余度)。

### 与上下文去重

调用方可传入当前上下文已有的记忆 id 列表，已注入过的不重复注入——长对话里这是最大的一笔浪费来源。

### 像人一样的记忆：四个可工程化的特征

用户要的「像人类」，翻译成可实现的机制是四条，不是玄学：

| 人类特征 | 工程实现 |
|---|---|
| 记住要点不记住字 | Fact 层存结构化断言，原文只作为溯源 |
| 情绪事件记得特别牢 | 引入**情感强度**作为独立打分维度；峰终效应：会话末尾与情感峰值额外加成 |
| 会重构，记不清细节但记得结论 | 折叠机制：多条情节合成摘要，原文降为可查不可见 |
| 近的事更清楚，远的事模糊 | 时近性衰减，重要度高的事衰减慢 |

情感维度是原方案漏掉的一项，而它对陪伴场景恰恰最重要——**用户不会记得 AI 说过什么，但会记得哪次对话让他有感觉**。

## 验证方式

1. **机制验证**：九类自动化测试，每类对应一条需求（R1-R4）
2. **行为验证**：演示脚本模拟三个月的对话，逐年看记忆库演化
3. **主观验证**：可视化界面上肉眼核对——问一个问题，看它选了什么、排除了什么、为什么
