# N4 架构契约 · 藏识 Alaya

版本 v1.0.0 ｜ 契约一旦发布，开发线只读不改，改动走 G2 回环

## 一、技术栈选型

| 层 | 选型 | 理由 | 降级 |
|---|---|---|---|
| 语言 | Python 3.13 | 本机已有，生态够 | — |
| 存储 | SQLite（单文件） | 零部署、事务、FTS5 全文、可单文件备份 | — |
| 向量索引 | numpy 矩阵 + 分段量化桶 | 十万级够用、无外部服务 | 无 numpy 时退化为纯 Python 点积 |
| 中文分词 | jieba（可选） | FTS5 中文检索质量 | 无 jieba 时用字符二元组 |
| HTTP 服务 | FastAPI + uvicorn | 自动 OpenAPI 文档、异步、性能好 | 无 FastAPI 时退化为 http.server 最小实现 |
| 前端 | 单文件 HTML + 原生 JS | 无构建链、可直接双击打开 | — |
| LLM | Provider 抽象（Ollama / OpenAI 兼容 / 规则） | 云端本地都可插 | 全部不可用时用规则抽取，系统不崩 |

**依赖纪律**：`alaya/core/` 内**禁止 import 任何第三方库**（numpy 除外且必须 try-import）。服务层与增强层可以依赖第三方。这保证核心记忆引擎可以在任何机器上跑。

## 三、数据模型

### 3.1 episode（事件层，只增不改）

| 字段 | 类型 | 语义 |
|---|---|---|
| id | TEXT PK | 确定性哈希 |
| session_id | TEXT | 会话 |
| seq | INTEGER | 会话内序号 |
| role | TEXT | user / assistant / system |
| text | TEXT | 原文，**永不修改** |
| t_event | INTEGER | 事件发生时间（epoch 秒） |
| t_ingest | INTEGER | 录入时间 |
| salience | REAL | 0-1 重要度 |
| access_count | INTEGER | 被召回次数 |
| last_access | INTEGER | 最后召回时间 |
| embedding | BLOB | float32 打包 |
| folded_into | TEXT | 被折叠进哪条摘要 |
| archived | INTEGER | 0/1 |

### 3.2 entity（实体层）

| 字段 | 语义 |
|---|---|
| id, name, norm_name | 规范化名（小写去空格）用于合并 |
| type | person / place / thing / concept / org |
| aliases | JSON 数组：昵称、代称 |
| attrs | JSON 对象：画像属性 |
| salience | 重要度 |
| first_seen, last_seen | 时间范围 |

唯一约束：`(session_id, norm_name)`。

### 3.3 fact（事实层，双时间）

| 字段 | 语义 |
|---|---|
| id | 主键 |
| subject_id | 主体实体 |
| predicate | 规范化谓词（工作在 / 住在 / 喜欢 / 讨厌 / 害怕 / 有…） |
| object_text | 客体文本 |
| object_entity_id | 客体若是实体则填 |
| polarity | +1 肯定 / -1 否定 |
| confidence | 0-1 |
| t_valid_from, t_valid_to | **世界时间**：何时为真（to 为 NULL 表示仍为真） |
| t_ingest, t_invalid | **系统时间**：何时录入、何时判定失效 |
| status | active / invalidated / superseded |
| source_episode | 溯源 |
| salience | 重要度 |
| embedding | 客体文本向量 |

**索引**：`(subject_id, predicate, status)`、`(t_valid_from)`、`(t_invalid)`。

### 3.4 hyperedge / hyperedge_member（主题层，n 元）

hyperedge：id, kind（主题/事件簇/关系网）, label, summary, salience, t_from, t_to, member_count。
member：edge_id, member_type（episode/fact/entity）, member_id, weight。

**这是超图，一条边连多个成员**——普通图的二元边表达不了"这段经历整体属于某个主题"。

### 3.5 state_slot（状态层，时间动力学核心）

| 字段 | 语义 |
|---|---|
| id, scope | scope = 主体实体 id |
| slot_key | 槽位名：job / city / relationship / mood_baseline / pet … |
| value_text | 当前值 |
| since, until | 何时起效、何时结束（NULL = 至今） |
| source_fact | 由哪条事实推导 |
| confidence | 置信度 |

**不变式**：同一 (scope, slot_key) 在任意时刻**最多一条** `until IS NULL`。

### 3.6 retrieval_log（检索审计）

id, ts, session_id, query, plan_json, selected_json, excluded_json, latency_ms, abstained。

## 四、核心算法契约

### 4.1 写入管线 `write.ingest_episode()`

```
输入: session_id, role, text, t_event
1. 入库 episode（不可变），计算 embedding
2. 抽取 → candidates{entities, facts, state_changes, theme_hint}
3. 对每个 fact:
   a. 找同 (subject, predicate) 的 active facts
   b. 判定 resolve_action:
      - 无候选 → ADD
      - 有候选且语义等价 → NOOP（但强化 salience）
      - 有候选且互斥（同槽不同值） → UPDATE（旧条 invalidated + t_valid_to）
      - 有候选且相反极性 → INVALIDATE
   c. 执行
4. state_changes: 关闭旧 slot（until=now），插新 slot（since=t_event）
5. 超边归组: 按实体重叠度 + 向量相似度，加入已有超边或新建
6. salience 打分（LLM 1-10 → 归一化 + 规则加成）
7. 事务提交
输出: IngestResult{added, updated, invalidated, noop, entities_new, edges_touched}
```

**必须幂等**：同一 (session_id, text, t_event) 重复写入返回同一 episode id，不产生重复事实。

### 4.2 检索管线 `recall.recall()`

```
输入: query, session_id?, as_of?, budget_tokens, top_k
1. 规划 plan：解析实体、时间词、意图类型（现在/过去/变化/偏好/无）
2. 三路召回:
   - dense: query 向量 × 候选向量，取 top N1
   - sparse: FTS5 关键词，取 top N2
   - graph: plan 中的实体 → 实体邻域（1-2 跳）→ 关联 fact/episode，取 top N3
3. 融合：RRF（Reciprocal Rank Fusion, k=60）
4. 重排 score（见 4.3）
5. 分带：must（state 层强制）/ high（>θ_h）/ fill（θ_l~θ_h）
6. MMR 去冗余，填充到 token 预算
7. 拒答判定：最高分 < θ_abstain → abstained=true，返回空证据 + 原因
输出: RecallResult{evidence[], scores{}, plan, abstained, reason}
```

### 4.3 打分公式（契约固定，改动需 G2）

```
raw = w_rel·rel
    + w_time·time_fit
    + w_sal·salience
    + w_graph·graph_prox
    + w_emo·emotion
    - λ_pol·polarity_penalty
    - λ_scope·scope_penalty

final = raw × (1 + α·log(1 + access_count))
```

| 分项 | 定义 |
|---|---|
| rel | 余弦相似度经**分位数归一化**（非 min-max，避免长尾压扁） |
| time_fit | 有 as_of / 时间意图时：落在时间窗内 1.0，窗外按距离指数衰减；无则 0.5 |
| salience | 静态重要度 |
| graph_prox | 1/(1+最短跳数)，无连通 0 |
| **emotion** | 情感强度 0-1：情感词分级 + 标点强化 + 峰终加成 |
| polarity_penalty | query 意图与事实极性冲突（问"喜欢"命中"讨厌"）时 1.0 |
| scope_penalty | 当前对话主体与该事实主体不一致时按距离扣分 |

默认权重：`w_rel=0.34, w_time=0.14, w_sal=0.20, w_graph=0.14, w_emo=0.18, λ_pol=0.35, λ_scope=0.20, α=0.08`。

### 4.3b 渐进式注入与预算约束（帕累托核心）

**这是整个系统最关键的一节。** 记忆的价值不是「被检索到」，是「在有限预算内被用上」。

#### 四级呈现

| 级 | 内容 | 成本函数 | 生成方式 |
|---|---|---|---|
| L0 | 指针：`[predicate:object]` | `tokens(s) ≈ 4 + len/1.6` | 从 fact 直接拼 |
| L1 | 三元组 + 时间 | L0 + 12 | fact 字段拼接 |
| L2 | 一句话摘要 | L1 + 25 | 折叠时预生成 / 原文截断 |
| L3 | 原文 | 原文长度 | episode.text |

#### 选择算法（预算约束下的边际收益贪心）

```
给定预算 B，候选集 C（含每条的四个级别）
已选 S = ∅，剩余 R = B
1. State 层优先：所有当前状态槽，强制注入 L1（通常 < 200 token）
2. 其余候选按 value_density 降序：
   value_density = final_score × level_weight / token_cost(level)
   level_weight: L0=0.55, L1=0.8, L2=1.0, L3=1.15
   （L0/L1 便宜，略微压低权重避免"全是碎片"；L3 完整，略微抬高）
3. 逐条尝试 L1 → 若冗余度 > θ 则跳过；否则注入
4. 若 R 仍充裕（> 30%）且候选有余，挑 top-N 升级到 L2/L3
5. 贪心终止条件：R < min_cost 或 value_density < 阈值
```

**为什么不是 top-k**：top-k 的切点由一个全局分数决定，一条 300 token 的原文和一条 20 token 的三元组会被同等对待。预算贪心按「每 token 换多少价值」排序，这才是帕累托前沿的定义。

#### 三层降级（token 紧张时的行为）

| 剩余预算 | 行为 |
|---|---|
| > 60% 预算 | 正常：事实 + 情节 + 部分原文 |
| 20%-60% | 收缩：只保留 State + 高价值 Fact，Episode 降为 L1 |
| < 20% | 极简：只保留 State 快照 + Top3 Fact 指针（约 60 token） |

**绝不超预算**。宁可少注入，也不截断——截断会造成半句话的误导，比没有更糟。

#### 冗余控制

MMR：`选择下一项时，得分 × (1 - λ·max_sim(候选项, 已选项))`，λ 默认 0.28。
另加事实级去重：同一 (subject, predicate, object) 只保留 salience 最高的一条，其余合并为 `mentions: n` 计数。

### 4.3c 情感强度计算

```
emotion = clamp( lexical_intensity × 0.6 + punctuation × 0.2 + peak_bonus × 0.2 )
```

- `lexical_intensity`：情感词表分级（0.3 弱 / 0.6 中 / 1.0 强），带否定翻转
- `punctuation`：连续感叹号、问号堆叠、省略号密度
- `peak_bonus`：会话最后 3 条 +0.15；该会话内 emotion 最高的一条 +0.25（峰终效应）

情感词表内置约 120 词，覆盖：喜欢/厌恶、开心/难过、焦虑/安心、愤怒/平静、亲密/疏离、疲惫/兴奋。


### 4.4 遗忘 `forget.run()`

```
R(t) = exp(-Δt / S)
S = base_strength × (1 + log(1+access_count)) × (0.5 + salience)
```

| 阶段 | 触发 | 动作 |
|---|---|---|
| 降权 | 每次遗忘周期 | 重算 R，写回排序用 |
| 折叠 | 同超边下 R<0.25 且 member≥4 | LLM 生成摘要 episode，成员设 folded_into |
| 归档 | R<0.08 且 salience<0.6 | archived=1，不进日常召回，可显式查询 |

**保护**：`salience>=0.8` 或 `pinned=1` 永不折叠、永不归档。

### 4.5 时间解析 `timeparse`

支持：昨天/今天/前天/上周/上周三/上个月/去年/三个月前/X 月 X 日/2024 年。
输出 `(start_ts, end_ts, granularity)`。无法解析返回 None（不猜）。

## 六、降级矩阵

| 缺失 | 行为 |
|---|---|
| numpy | 纯 Python 点积，慢 10-50 倍，功能不变 |
| jieba | 字符二元组 + 停用词，召回率降但可用 |
| Ollama embedding | 哈希伪向量（确定性，可测但不语义），并在 /v1/stats 标记 `embed_degraded=true` |
| LLM | 规则抽取（正则谓词 + 状态词表），抽取精度降，系统不崩 |
| FastAPI | http.server 最小实现，仅核心 5 个接口 |

**降级必须显式可见**，不允许静默降级——这是审计要求。

## 七、性能预算

## 八、代码纪律

1. 每个公开函数必须有 docstring 说明输入输出与副作用
2. 事务边界清晰：写入要么全成要么全回滚
3. 所有时间戳统一 epoch 秒（float），禁止混用毫秒
4. ID 用确定性哈希，保证幂等
5. 禁止在 core 里 print，用 logging
6. 测试必须覆盖：幂等性、并发写、时间旅行、拒答、降级
