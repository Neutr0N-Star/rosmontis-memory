### 条件边的定义

每条边都带触发条件，不是无条件流转：

| 边 | 条件 |
|---|---|
| G1→F | 存在 severity=致命 的条目 |
| G2→F | 存在会导致"结果不可信"的机制错误 |
| G3→F | 存在 P95 延迟 > 500ms 或并发失败率 > 0 |
| G4→F | 存在"阻塞级"集成问题 |
| F→V | 该批次所有修复点已落地并自测通过 |
| V→交付 | **全部**验收条件逐条为真 |
| V→F | 任一条验收条件为假，且回环次数 < 2 |

## 第三轮：机制升级（不是修 bug，是换机制）

评审留下的三个"需要产品决策"的缺口，找到了现成答案：

| 缺口 | 来源 | 采纳了什么 | 落地方式 |
|---|---|---|---|
| 情感峰终从未生效（缺"会话结束"） | Ori Mnemos 的 session lifecycle + Letta 的 sleep-time compute | `close_session()`：峰值条 salience +0.25、末尾 3 条 +0.15，然后触发沉淀与遗忘 | 新增接口 `POST /v1/sessions/{sid}/close` |
| 语义扩散只能靠向量（用户第一条需求） | FieldMem（arXiv 2602.21220，热方程 `∂φ/∂t = D∇²φ − λφ + S`） | 连续场的拉普拉斯在图上就是"邻居均值"。用超边建邻接表，命中节点沿边扩散 2 跳，γ=0.45 | 新增 `core/memory_field.py` + recall 里的 `_expand_by_field` |
| 遗忘会删掉枢纽节点，图断成孤岛 | Ori 的 Tarjan 割点保护 | 用度中心性近似（成本低一个数量级），高连接度节点永不归档 | `memory_field.critical_nodes()` |

另外两处借鉴：

- **ACT-R 基础激活**替代单一 `access_count`：`A = ln(Σ t_j^-0.5) + B`。同样访问 5 次，昨天访问和一年前访问不该同分。
- **三空间衰减率**：identity 0.1x / knowledge 1.0x / operational 3.0x。比"统一衰减率 + 重要度调制"更贴近真实。

### 实测

会话 5 条：`[天气, 累, 特别难受想哭, 想通了, 晚安]`

关闭后：

| 记忆 | emotion | salience |
|---|---|---|
| 特别难受，想哭 | 0.49 → **0.69** | 0.53 → **0.93**（保护级） |
| 不过后来想通了（结尾） | 0 → 0.07 | 0.38 → 0.53 |
| 晚安（结尾） | 0 → 0.07 | 0.38 → 0.53 |
| 今天天气不错 | 0 | 0.38（不变） |

这就是"人记得最难受的那一刻和结尾"。

扩散激活：查"团子"能把同属"养狗"主题的另外两条一起拉出来——向量检索做不到这一点，因为它不知道这三条属于同一个主题。

### 未采纳

- **不引入 JAX / PDE 求解器**。FieldMem 的连续场需要 1536 维投影到 2D 流形 + 稀疏哈希，工程重量远超收益。图扩散在语义关联上给出的是同一件事的离散近似，且复用已有结构。
- **不引入多智能体场耦合**。当前场景是单 agent。
- **不照抄 Ori 的 markdown-on-disk 存储**。它的优势是"人可读、git 可版本"，但它的检索恒定为 ~850 token 是因为做的是笔记检索；本系统要处理带时间与状态的事实，SQLite 更合适。

## 第四轮：NeuralMemory 的取舍

来源：`github.com/nhadaututtheky/neural-memory`（v4.62.0，1066 commits，7800+ tests，MIT）

它做了个大胆选择：**免费版完全不用向量**，纯 FTS5 关键词 + 图扩散 + 突触。这个选择本身证明了「图 + 扩散」这条路能走通。

### 采纳了什么

**四级反射深度**（它的 ReflexPipeline：INSTANT / CONTEXT / HABIT / DEEP）

| 深度 | 触发 | dense/sparse/graph | 跳数 | 预算系数 |
|---|---|---|---|---|
| instant | 短问句 + 身份/现状类 | 6 / 6 / 0 | 0 | 0.45 |
| context | 一般问题 | 30 / 30 / 18 | 1 | 1.00 |
| habit | 含"为什么/以前/变化"或有时间指示 | 55 / 55 / 35 | 2 | 1.25 |
| deep | 含"总结/所有/回顾/列出" | 90 / 90 / 60 | 3 | 1.60 |

实测：`800` 基础预算下，「我住哪」走 instant 只用 360，「总结所有经历」走 deep 给到 1280。**问一句话不必扫全库**。

**对话场景调参**（它的 chat-heavy preset）：衰减快、新近偏差大、扩散浅、回复紧凑。这四个方向已体现在三空间衰减率和 depth 参数里。

### 明确不采纳

**纯 FTS5 无向量**。它这么做是为了零成本零 API，但代价是「authentication improvements 查不到 JWT rotation」——它自己的 Pro 版就是靠 HNSW 补这个。中文 FTS 的分词问题更严重。本系统保留稠密召回（bge-m3），FTS 只做补充腿。

**24 种显式关系类型**（CAUSED_BY / LEADS_TO / CONTRADICTS / RESOLVED_BY…）。这是它比本系统强的地方——超边只做了归组，没做语义标注，所以没法沿"CausedBy"单条关系链推理。

但要做它，得改抽取层（让 LLM 产出关系类型）+ 改 schema（成员级 relationship）+ 改扩散（按关系类型过滤路径）。这是一次结构性改动，不是补丁。**列为下一版第一优先**。

**Pro 的商业分层**。自用场景无关。

### 一句话判断

这个项目验证了第三轮的方向（图 + 扩散激活 + 显式关系），而且证明了「不靠向量也能做记忆」是可行的——但只在不要求语义召回的前提下。

## 第五轮：主动记忆（harness 层）

设计文档：`docs/09-主动记忆设计.md`

这一轮不是修 bug，是加一层：从「她被动被检索」到「她自己写」。

### 核心判断

**流水账不是写得少，是结构少一层。** 四段结构：`what / noticed / means / next`。
**只有 what 的条目不许进笔记层**——这是硬闸，写在写入路径上。

**分层不按时间分，按「将来什么时候用得上」分**：
速记（消耗品，用完清）/ 笔记（资产，会衰减）/ 沉淀（结论，只重写）/ 人设（身份，0.1x 衰减）。

**主动必须有闸门**，否则人格漂移加越改越乱：频率闸（单次会话 ≤2 次改人设）+ 幅度闸（≤200 字）+ 来源闸（必须来自已存在的笔记）+ 留痕闸（可回滚）。

### 寄生式实现（关键决策）

不新建平行系统：

| 新东西 | 寄生点 |
|---|---|
| 笔记 | `episode` 表 + `source='notebook'` |
| 速记 vs 笔记 | 现有 `tier` 字段：`inbox` / `retrieval` |
| 升格到沉淀 | 现有 `pages._append_to_page` |
| 升格到人设 | 现有 `persona.add` |
| 笔记检索 / 衰减 / 激活 | **零改动**，因为已经是 episode |

只新建了一张表 `notebook_promotion`（审计 + 回滚用）。

### 热重载

`build_context(query)` 一次返回 persona + memory 两块。人格每次现编译，改完下一轮就是新的——**不需要监听文件变化**，因为不存在缓存。

### 验收（七条全过）

| 标准 | 结果 |
|---|---|
| A1 只有 what 进速记层 | 通过（`tier=inbox`） |
| A2 四段进笔记层并被检索到 | 通过（`tier=retrieval`，recall 命中） |
| A3 升格后 build_context 立刻反映 | 通过（True）/ 回滚后 False |
| A4 频率闸 | 通过（第 3 次拒绝，理由明确） |
| A5 幅度闸 | 已实现（>200 字拒绝） |
| A6 可回滚 | 通过 |
| A7 速记层整理后清空 | 通过（4 条同主题合成 1 条，inbox 归零） |
