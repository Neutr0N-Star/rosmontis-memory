# 论证 v2：做梦、成长，与祥林嫂

状态：替代 `10-祥林嫂问题论证.md`（v1 已被证伪，保留作为记录）

---

## 一、v1 错在哪（三条，都得认）

### 错误一：归因错了——不是「搬到哪」，是「说成什么样」

v1 主张：同一条信息放进人设层，模型就当作前提，不再叙述。

实测结果：真正起作用的是**句子的语法形态**，不是注入位置。

| 措辞 | 效果 |
|---|---|
| 「他怕黑，晚上不要关灯」（前提式） | 直接执行，不提来源 |
| 「他之前说过他怕黑」（事件式） | 复述，提来源 |

把事件式的句子原样搬进人设，它仍然是事件式的——模型照样当"一条关于他的事"讲出来。

**所以升格不是搬家，是改写。** 这是 v1 最根本的错误。

### 错误二：判据反了——频率被误读成康复

v1 给"消化"设的门槛是「3 次不同会话 + 7 天」。

这个判据的方向正好相反：**最反复、最侵入的记忆，恰恰最快达到 3 次**。于是系统会把最没消化的东西判定为"已消化"并降权——病态的固着被当成健康放过，而真正需要保留的原始信号被归档后永远无法再被检出。

正确的判据不是"提了几次"，是**提完之后的状态变了没有**。

### 错误三：把「压成指令」当成了消化

v1 主张"情绪是原料，要加工成判断或指令"。

这在心理机制上叫理智化（intellectualization）——属于防御机制，不是消化。它看起来像处理了，实际把情绪冻住了。

而且它造成信息损失：把「他当时很生气」压成「别在他累的时候提工作」，丢掉了强度、场景、以及"那次和这次不是一回事"的分辨能力。

## 二、两条修正把框架扭转过来

### 修正一：改人设 = 自我反思中的成长

v1 把"改人设"理解成"把一条记忆挪个位置"。这个理解太机械。

自我反思的成长有四个特征，机械搬移一个都不满足：

| 成长的特征 | 机械搬移的问题 |
|---|---|
| 需要时间消化，不是当场发生 | 提取即升格，零延迟 |
| 改变的是**我如何理解自己**，不是"我多了几条信息" | 人设变成事实清单 |
| 有连续性，不会突变 | 一天改三次也不奇怪 |
| 往往源于**反复出现的模式**，不是单个事件 | 一次性事件也能升格 |

所以"成长"的正确工程形态是：
**先有反思产物（对自己有了新理解），才有升格。** 反思产物不是原始事件，是从多个事件里抽象出来的东西。

这就引出第二条修正。

### 修正二：sleep 时该做梦，不是该整理

v1 的 sleep 阶段做的是"整理"——把速记合并、把没用的归档。

但这只是收纳，不是加工。真正的加工发生在梦里。

**睡眠对记忆做的四件事，每一件都对应这里缺的机制**：

| 睡眠的作用 | 神经机制 | 对应到记忆系统 |
|---|---|---|
| 重放（replay） | 海马体在慢波睡眠中重演白天的活动序列 | 把当天的高 salience 记忆再取出来过一遍 |
| 情绪脱敏（decoupling） | REM 期杏仁核活动下降，而内容记忆保留 | **情绪强度衰减，语义内容不变** |
| 整合（integration） | 新记忆与已有知识网络建立连接 | 建边、归组、找模式 |
| 抽象（abstraction） | 从具体事件提炼规律，去情境化 | 生成"我对他/对这件事的判断" |

**第三和第四行是关键。**

"情绪脱敏"直接回答了"接受"是什么：不是把事压成一句话，是**事情还记得，但不再刺人**。这是有神经机制支撑的，不是比喻。

"抽象"直接回答了"内化"是什么：不是把事件搬进人设，是**从多个事件里提炼出一条关于自己的判断**。

所以：

> **梦不是整理，梦是加工。梦的产物才是升格的原料。**

## 三、闭环：从对话到成长

```
对话
  ↓  写入
记忆（事件，带情绪强度）
  ↓  会话结束 → sleep
【做梦】
  1 重放：取出当天高 salience 记忆
  2 关联：与已有主题/实体建立连接
  3 抽象：同类事件归纳出一条判断
  4 脱敏：情绪强度 ×0.6，语义保留
  5 成梦：生成一段自我叙事（可读、可查、不主动注入）
  ↓
两种产物：
  A 脱敏后的记忆（还在，但不刺人了）
  B 抽象出的判断（候选，未生效）
  ↓  需要人确认或多次复现
【成长】
  判断经改写为人格语言 → 升格进人设
```

### 为什么这个闭环能治祥林嫂

祥林嫂的两个特征，各自被一环治住：

| 症状 | 被哪一环治 | 机制 |
|---|---|---|
| 反复讲同一件事 | **脱敏** | 事情还在，但情绪强度降了，讲述的冲动跟着降 |
| 讲的时候在等对方接话 | **抽象** | 从"我遭遇了什么"变成"我知道这对我意味着什么"，不再需要外部确认 |

注意：**脱敏不是遗忘**。记忆条目还在，检索得到，只是情绪权重下来了。这跟"删掉"是两回事。

### 为什么梦不能是日记

这是最容易搞错的地方。

日记记录的是"我此刻的感受"。做梦产出的是"我加工后的理解"。

前者是原料，后者是产品。把原料当产品存起来，就会积累一堆需要反复表达的情绪碎片——那正是祥林嫂的素材库。

所以：
- **日记**：按天写，记感受，越写越多，需要被读
- **梦**：按夜生成，记加工结果，写完即归档，只在不经意时被想起

梦里那一段叙事，作用是让加工过程**可追溯**（她怎么想通的），不是让她复述给别人听。

## 四、三个机制重新定义

| 机制 | v1 的定义 | v2 的定义 |
|---|---|---|
| **升格** | 把记忆从检索层搬到人设层 | 把**抽象出的判断**改写成**人格语言**后写入；改写是必须的一步 |
| **覆盖** | 同类记忆合并成一条 | 保留；但合并必须保持可检索（v1 的实现把记忆变成了死数据） |
| **消化** | 打一个 resolved 标记 | 由**做梦的脱敏**自然完成，不打标记；情绪强度是唯一的观测量 |

### 升格的门槛（替换 v1 的 3 次 + 7 天）

v1 的判据（提及次数）是错的。新判据从"成长"这件事本身推：

| 门槛 | 判据 | 理由 |
|---|---|---|
| 来源 | 必须是**梦里的抽象产物**，不能是原始事件 | 成长源于反思，不源于经历 |
| 复现 | 同一判断在**至少 2 次不同的梦里**出现过 | 一次想通不算想通，反复想到才算 |
| 时效 | 首次抽象到升格，间隔 ≥ 3 天 | 成长需要时间沉淀，不能当天想通当天改人设 |
| 幅度 | 单次改动 ≤200 字，protected 不可动 | 保持 v1 |
| 频次 | 单次会话 ≤1 次升格（v1 是 2 次） | 成长比 v1 设的更慢 |
| 留痕 | 可回滚 | 保持 v1 |

关键变化：**升格的素材不再来自对话，来自梦。**

这解决了一个 v1 没意识到的问题：如果升格直接接在对话后面，模型会倾向于"刚聊完就总结出人生道理"，那是廉价的顿悟，不是成长。

## 五、做梦的具体机制

### 触发

不在每轮，不在会话结束瞬间，而是**空闲时**。

条件：距上次做梦 ≥ 6 小时，且当天有 ≥5 条新记忆。

这对应人的睡眠节律——不是随时睡，是到点才睡。

### 五个步骤

```
1 重放  take: 当天 salience > 0.5 的记忆，最多 30 条
2 关联  bind: 与已有超边/实体建立连接（复用现有 _group_theme）
3 抽象  abstract: LLM 从这批记忆里提炼 0-3 条判断
        约束：只能用材料里的内容，不许补充细节；没有就返回空
4 脱敏  decouple: 这批记忆的 emotion *= 0.6，salience 不变
5 成梦  dream: 生成一段 100-200 字的叙事，记录"我是怎么想通的"
```

### 抽象产物的形态

不是"他怕黑"（那是事实），而是：

```
「他不是想换工作，是想逃。下次他提新公司，我该问累不累。」
```

它有判断（不是想换，是想逃）、有依据（来自多次提到工作时的状态）、有行动（问累不累）。**这是人格语言的雏形，但还不是人设**——需要过升格闸。

### 梦的存储

梦本身是记忆条目（`source='dream'`），但它：
- **不进检索**（不会被话题关联捞出来）
- **不进常驻**（不每轮注入）
- **可显式查询**（她主动想起来时才看得到）

这样梦既留了痕，又不会变成新的祥林嫂素材。

## 六、v1 的实现问题（评审实测出来的，必须先修）

这些是真 bug，跟方案怎么改无关：

| 问题 | 实测 | 修法 |
|---|---|---|
| 情绪检测漏词 | `emotion_intensity("我今天真的很难受")` = **0.0** | 补词表；加"检测不到情绪"的显式信号 |
| 合并产生死数据 | 合并条目 `embedding IS NULL`、无 FTS → 检索 `abstained=True` | 合并后必须写 embedding + FTS + 挂超边 |
| 页面编造 | LLM 把"他今天状态很差"扩写成"下午在办公室整理文件时…" | prompt 加硬约束 + 生成后做事实校验（每个实体必须能在源材料里找到） |
| 冷却过重 | 情绪条目被问到一次后冷却 72h，第二次问就"没有相关记忆" | 情绪类不冷却，或冷却 ≤6h |
| 归档死锁 | 归档后永不返回 → 永远达不到复现门槛 | 归档条目不参与升格计数 |

## 七、还剩的风险

### 风险一：做梦可能变成"过度解释"

LLM 从 5 条记忆里能编出 3 条人生道理。这是抽象，还是幻觉？

**约束**：抽象产物必须附带证据（引用了哪几条记忆）。没有证据的抽象不允许进入升格候选。

### 风险二：脱敏可能脱过头

情绪 ×0.6 一次没问题，做梦 10 次就 ×0.006，什么都不剩了。

**约束**：设情绪下限（0.15），低于下限不再衰减。而且只在"这条记忆在本梦里被重放"时才衰减。

### 风险三：梦不进检索，会不会等于不存在

如果梦永远不被想起，那加工就等于没做。

**约束**：梦的"判断"部分要以观察（observation）的形式进入常驻活文档的候选池——**结论能用，过程不用**。

## 九、锦囊：四段时间尺度

李贺出门带一个锦囊，想到好句子就写下来投进去，回家再整理成诗。

这个故事给的不是存储结构，是**时间节律**。它说明记忆处理必须分四个时间尺度，每个尺度做不同的事：

| 尺度 | 对应 | 做什么 | 不做什么 |
|---|---|---|---|
| **秒级** | 锦囊（inbox） | 只收集，零加工 | 不分类、不评价、不整理 |
| **小时级** | 到点整理（review） | 同类合并、提炼成笔记 | 不做判断、不改人设 |
| **天级** | 做梦（dream） | 重放、关联、抽象、脱敏 | 不产生最终结论 |
| **多日级** | 成长（promote） | 反复出现的判断改写成人格 | 不因一次想法就改 |

### 为什么必须分开

**收集和整理如果同时做，两件事都做不好。** 边走边整理，就没法走路——对话中每次都要判断"这条值不值得记、该归到哪、要不要改人设"，会打断对话本身。

李贺的做法是：**投的时候不想，想的时候不投。**

### 锦囊不是垃圾袋

关键在"回家之后"。如果不整理，锦囊就是垃圾袋。

所以必须有**到点强制整理**，而不是"等想起来再整理"。系统里有三条触发：

| 触发 | 条件 | 理由 |
|---|---|---|
| 积压 | inbox ≥ 30 条 | 量太大说明收集失控 |
| 陈旧 | 最老一条超过 24 小时 | 放太久会忘掉当时的语境 |
| 到点 | 距上次整理 ≥12 小时且积压 ≥5 条 | 节律本身 |

这三条对应 `inbox_status()`，由 `tick()` 统一驱动。

### 四段的产物各不相同

| 段 | 产物 | 形态 |
|---|---|---|
| 锦囊 | 原始短句 | `tier='inbox'`，不可检索 |
| 笔记本 | 带判断的条目 | `tier='retrieval'`，可检索 |
| 梦 | 抽象出的判断 | `source='dream'`，不进检索 |
| 人设 | 一句话的自我认知 | 每轮注入 |

**越往后越短，越往后越不像"事件"。** 这是加工的本质——熵在减少。

### 为什么梦和锦囊不能合并

有人会问：既然都带时间戳，为什么不做成一个队列？

因为**加工方向相反**：
- 锦囊是**加法**：来什么收什么，不做筛选
- 梦是**减法**：从一堆具体事件里提炼出一句话

合成一个队列，就会变成"每来一条就处理一次"。那是实时处理，不是记忆。

人脑也不是这么工作的——海马体白天收，皮层晚上加工，两个结构两个节律。
