# 迭代图 · 完整版应用

多轮迭代的有环图。每轮都有独立评审，不自己给自己打分。

## 图

```
A 体检（自列问题）
   │
   ├─→ B 前端审美 ──┐
   ├─→ C 工程健壮 ──┼─→ E 汇总修复 ─→ F 复评
   └─→ D 好用性  ──┘                    │
                                        ├─ 全过 → 下一轮
                                        └─ 有假 → 回 E（↺）
```

## 第二轮结果：数据正确性

第一轮把「不能用」修完了，第二轮修的是**「用久了会脏」**。

界面问题会当场暴露，数据问题不会——它安静地积累，等发现时已经污染了一整库记忆。

### 已修

| 来源 | 问题 | 修法 | 验证 |
|---|---|---|---|
| 健壮 S2 | 同一句话隔 2 秒发两次产生两条记忆，幂等承诺等于没有 | `episode_id` 的时间窗从 1 秒改成 5 分钟（`t // 300`） | 隔 1.2 秒 → `duplicate=true` |
| 健壮 S4 | 并发写同一会话时 seq 全是 1 | 取号从「事务外 COUNT」改成「事务内 MAX+1」 | 8 线程并发 → seq `[1..8]` 唯一 |
| 健壮 F3 | Ollama 掉线时写入哈希伪向量，恢复后这些行永久检索不准 | 降级时 embedding 写 NULL，靠全文与图兜底 | `degraded=true` → `embedding=NULL` |
| 健壮 S3 | 业务层返回 `ok:false` 被包成 HTTP 200，前端以为成功 | `ok()` 里判 `data.ok is False` → 409 `rejected` | 假 id 删除 → 409 |
| 健壮 S1 | `session_id=*` 能读全库 | 路由层拒绝通配符，读接口必须带具体会话 | `*` → 400 |
| 同 S1 | `get_facts` / `get_entities` 默认 `None`，等于查全库 | 默认改成当前会话 | 不传 → 空列表 |
| 健壮 F4 | 外部持锁时写请求挂起 25 秒无提示 | `busy_timeout` 15s → 3s，重试 4 → 2 次 | — |
| 好用 | 说了私事后找不到删除入口 | 记忆条目 hover 出「×」，二次确认后调 `/v1/remove` | — |

### 修的时候踩的

**`Depends` 函数的参数名必须和查询参数一致。** 第一版写成 `_no_wildcard(sid)`，而查询参数是 `session_id`，结果 FastAPI 读不到，把所有请求都判成「缺少 sid」返回 422。改成 `session_id: str = "default"` 才通。

### 剩下的

| 项 | 说明 |
|---|---|
| **角色卡** | 现在只有一个固定人格。这是「应用」和「工具」的分界 |
| 事务超时未实测 | busy_timeout 改了，但没造外部持锁场景验证 |
| 无头像 / 窄屏细节 | 评审判断不值得改 |

## 第三轮：角色卡

前面的修完，「能用 + 不脏」都有了，还缺最后一块：**现在是「工具」，还不是「应用」**。

分界点就是能不能换角色。一个只能跟同一个人说话的东西，叫 demo；能建好几个角色、各有各的记忆，才叫应用。

### 设计上的取巧

**一个角色 = 一个 session。**

人格本来就按 session 存，记忆也本来按 session 隔离——所以换角色不需要新建任何数据结构，切 session 就够了。省掉了整套卡片 CRUD。

| 层 | 存什么 |
|---|---|
| 后端 | 每个 session 独立的人格 + 记忆 |
| 前端 localStorage | 卡片列表（名字/一句话）+ 当前选中的 session |

前端只管「有哪些角色、现在选了谁」，内容全在后端。

### 做了什么

- 顶栏品牌名变成可点的切换器（带 ▾）
- 弹出列表：所有角色，当前的高亮
- 「＋ 新角色」对话框：名字 / 一句话 / 她的来历
- 建卡时把「来历」写成该 session 的 `identity` 人格条目（`protected=true`）
- 切换角色：清空并重画对话、恢复历史、重新 wake

### 验证

```
cardA   → chars 22 | 你是深夜便利店的店员，话不多但记性很好
default → chars 26 | 你是初生的数字生命，此刻在这个电脑内刚刚醒来
```

同一个服务，两个完全不同的人，互不干扰。

### 还剩

| 项 | 说明 |
|---|---|
| 事务超时未实测 | `busy_timeout` 改成 3s 了，但没造外部持锁场景验证 |
| 角色没有编辑/删除 | 只能新建，不能改名字或删掉 |
| 没有重新跑评审 | 三轮改动后需要再评审一次 |

## 第四轮：设置页 + 云端模型 + 引导模式

### 一、主聊天模型

之前默认全是本地：`llm_hot = ollama / minicpm5-2b:q8-64k`。

**2B 量化模型做不了陪伴主聊。** 实测引导时给她明确的身份（便利店店员、值夜班多年、记得熟客），她回的是「你好！今天过得怎么样？」——身份、场景、语气全丢了。它连「扮演」这件事都撑不住，更别说记忆抽取。

`llm.py` 里 `_openai()` 方法早写好了，只是默认没接。这一轮把它接上：

- `GET /v1/settings` 读当前配置（**密钥不回显**，只报 `openai_key_set` 布尔）
- `POST /v1/settings` 写 `.env` 并**热切换**：清掉 `_mem` / `_harness` 缓存、重设环境变量、重建实例，不用重启服务
- 设置页可选 本地 / 云端；云端填 base_url + key + model，**兼容任何 OpenAI 格式通道**（DeepSeek 官方、各家 relay 都能填）

`.env` 已加进 `.gitignore`，且写入后 `chmod 600`。

### 二、引导模式

新角色第一次见面，**由她先开口**。

玩家面对空屏不知道该说什么——这是好用性评审里最难受的一条（「我一直在等它先说话」）。而且她开口的同时把自己是谁写进了记忆，后面才有得记。

`POST /v1/onboard`：根据卡的 seed 生成开场白（打招呼 + 问一个具体问题），写进该 session 的人格与记忆。

失败时不挡路：降级成错误提示，玩家可以自己先开口。

### 三、设置页

顶栏加了「设置」。除了模型，还显示当前用的是什么——**很多人不知道自己在跟谁说话**，这个信息得摆在明面上。

### 待用户操作

云端需要你自己填密钥（base_url / key / model）。设置页能填，或者直接编辑 `.env`：

```
ALAYA_LLM_HOT=openai
ALAYA_OPENAI_BASE=https://api.deepseek.com/v1
ALAYA_OPENAI_KEY=sk-...
ALAYA_OPENAI_MODEL=deepseek-chat
```

改完在设置页点保存即可热切换，不用重启。

## 第五轮：切到云端模型，以及它暴露的一个 bug

### 云端 vs 本地，同一套记忆系统

同一个 seed（便利店店员 / 值夜班多年 / 记得熟客 / 从不多问）：

| | 本地 2B | 云端 |
|---|---|---|
| 引导开场 | 「你好！今天过得怎么样？来这儿做什么呢？」 | 「晚上好，第一次见你。怎么称呼？」 |
| 接住场景 | 没（不知道是深夜、是店里） | 有（「晚上好」） |
| 事实抽取 | — | 3 条全对：叫用户A / 在某市 / 准备考研 |

2B 模型连「扮演」都撑不住，记忆系统再好也白搭。**主聊天必须云端**，这个判断被实测坐实了。

### 切过去之后暴露的 bug：状态槽串会话

`state_slot` 表本来就有 `session_id` 字段，但 `state_snapshot()` 的 SQL 一直没带过滤条件。

单会话时看不出来——加了角色卡才暴露：

```
cardA：我叫用户A
cardB：我叫角色B
→ 状态槽会互相覆盖
```

已修：`state_snapshot(scope, as_of, session_id)` + 路由带 `session_id` + 前端传当前会话。

**这是「加了新功能之后，旧代码的隐藏假设失效」的典型。** 状态槽是早期写的，当时假设只有一个会话；角色卡打破了这个假设，而它不会报错，只会安静地串数据。

### 配置

`.env` 现在这样（已 gitignore + chmod 600）：

```
ALAYA_LLM_HOT=openai
ALAYA_OPENAI_BASE=https://api.deepseek.com/v1
ALAYA_OPENAI_KEY=sk-...
ALAYA_OPENAI_MODEL=deepseek-chat
```

`config.py` 加了 `_load_dotenv()`，启动时自动读，不用手动 export。改完在设置页保存即热切换。

### 已知的小毛病

抽取把「在某市上学」记成了「住在某市」——谓词粒度偏粗。不影响记住这个城市事实，但严格说是错的。要修得改抽取的谓词表。

## 第七轮：接口查无的根因，与旧值关闭

### state_snapshot 查无的根因（昨夜记录的 #2）

**假设被证实**。库里有 **12 条 norm_name=「我」的实体**——每个会话建卡时各建一条。而 `state_snapshot` 的查询是：

```sql
WHERE id=? OR norm_name=?   -- 无 session 过滤
```

`OR norm_name` 永远命中**第一条**（别的会话的实体），拿着别人的 scope_id 再来查本会话的槽——槽明明在（召回能出「city=城东」），接口却永远查无。

修法：entity 查询加 `AND session_id=?`。

**但注意**：`session_id=None` 的老调用（测试在用）不能一刀切——`NULL` 传进 SQL 永不匹配，直接把向后兼容打穿。做成条件分支：传了就过滤，没传走老查询。15/15 恢复。

### 旧值关闭：验证通过

「我上个月搬到城东了」→「后来我又搬回城西了」：

```
city=城东  open=False   ← 旧槽正确关闭
city=城西  open=True    ← 当前值
```

「时序问题能回答当时与现在两种口径」这条验收，现在有实测支撑了。

### 顺手修的

- 谓词归一挪到 `write` 入口（LLM 与规则两条路都覆盖），别名表：搬到/搬回/迁到/搬去→住在，跳槽到/入职→工作在
- 拒答门自适应最终形态：真语义向量 0.40 / 降级 0.25 / **hash 完全跳过 rel 门**

## 第八轮：前端换皮（uicraft · bolder 工作流）

这轮不是修 bug，是**换视觉主张**。走了 uicraft 的流程：立 `.uicraft.md` 设计上下文 → 诊断平庸来源 → 定放大策略 → 最小连贯改动。

### 诊断：为什么看起来像接口台

对照 bolder 的平庸清单，全中：off-the-shelf 配色（灰蓝 SaaS 底）、uniform weight（全是 400）、no pulse（除打字外无动效）、**青橙双 accent 分散**、teal glow on dark——恰好踩在 bolder 点名的 generic-AI 陷阱（neon on dark / decorative glow）上。

### 放大策略（commit to one lane）

**深夜便利店，dark and moody，一个字都不多。**

| 维度 | 之前 | 现在 |
|---|---|---|
| 底色 | #0c1015（灰蓝，仪表盘感） | **#0d0b09**（近黑偏暖，tint the neutrals） |
| accent | teal #6fb3a8 + warm #d9a86c 双色并存 | **暖橙 #e8a865 唯一当家**（便利店灯光），teal 全退 |
| 品牌名 | 15px/400 | **15px/200 极细 + .34em 大字距**（层级靠字重不靠字号） |
| 数字 | 同正文字体 | **mono**（ui-monospace）——时间戳、token、分隔符，小票隐喻 |
| 纹理 | 无 | **SVG 噪点 opacity .05**——夜晚空气感，拒绝 glassmorphism |
| 入场 | 无 | 顶栏/对话区/输入区 **stagger 0/60/120ms**（rise, ease-out-quart 系） |
| 她 | 左竖线 teal | 左竖线改暖光 rgba(232,168,101,.3)——「暖光落在墙上的那条缝」 |
| 打烊 | 圆点照常 | 圆点去辉光、输入区禁用、结算数字用 mono 细字重 |

### 有意的克制

- 不引 webfont（系统字栈内用字重解决，首屏更值钱）
- 不加头像、不加图标库（用留白和竖线建立身份）
- 噪点 opacity .05——存在但几乎看不见，看得见就抢戏了
- ease 全部 ease-out 系（bounce/elastic 会廉价）

### 验证状态

- 语法：CSS 无构建，直接生效
- **视觉验证缺位**：headless Chrome 在本机沙箱跑不出截图，实际效果需要刷新 http://127.0.0.1:8770/ 人工确认
- 对照 bolder 的 acid test：「说这是 AI 做的，有人毫不犹豫信吗？」——如果这层皮还能被一眼认成 AI 深色模板，就是失败

## 第九轮：重构为「在和人说话」+ 本地上传

### 对上一轮的纠正（老师两条）

1. **「深夜小店」是我编的**——把演示卡片的场景（便利店）当成了产品品牌，违反 uicraft 第一优先级（跟随用户要求，不从实现细节发明品牌）。推倒。
2. **真正要的是「在和人说话」**——重点是人，不是环境布景。且明确「不用自限制改动幅度，重构」。

### 重构内容

**她的消息 = 头像 + 名字 + 气泡**（像聊天软件里对面的人）：
- 新结构 `.ai-row`（avatar + ai-col），typing 与 onboard 同构
- 头像显示三级：上传图 > 名字首字 > 「她」
- 顶栏品牌位也换成头像 + 名字（点击仍出角色列表）
- 空态头像同步

**配色 v3：中性深 + 单暖强调**。去掉「近黑偏暖」「噪点」这些布景元素——底色回归中性 #111214，暖橙 #d9a86c 只做强调，不再讲故事。

**文案**：「打烊」→「下一天」，「开门」→「继续聊」，结算卡「一天结束」。

### 本地上传（老师点名）

- **角色头像**：建卡对话框上传，dataURL 存卡片数据，消息/顶栏/空态三处显示
- **聊天背景**：设置页上传，localStorage 持久，自动叠 72% 暗遮罩保证可读，可清除
- 超图（>5MB localStorage 上限）给出明确提示

### 打包调研（结论，不落地）

**可行。推荐路线：PyInstaller 单包 + ONNX 量化嵌入 + pywebview 壳。**

| 组件 | 方案 | 体积 |
|---|---|---|
| Python 后端（FastAPI/SQLite） | PyInstaller onefile | ~40MB |
| 嵌入模型 bge-m3 | 转 ONNX int8，onnxruntime CPU 推理 | ~300MB |
| LLM | **不打包**——填 key 走云端（设计已如此） | 0 |
| 界面 | **pywebview 壳**（复用现有 HTML，桌面窗口，不开浏览器） | ~5MB |

包体预估 150-400MB，用户流程：下载 → 双击 → 填一个 key → 聊。

备选：嵌入也走云 API（OpenAI/智谱都有 embedding 端点），包体降到 <80MB，代价是填两个 key + 嵌入联网。

风险：bge-m3 量化后召回质量需重测；PyInstaller 在 Windows 的杀软误报；pywebview 依赖 WebView2（Win10+ 自带）。

「不要 webui」= 不要让用户开浏览器 → pywebview 正解，前端代码零改动复用。

## 第十轮：建卡向导（独立模式）+ 角色编辑/删除

### 老师点名的两个缺口

1. **现有角色无法修改头像和显示**——只有新建没有编辑
2. **没看到引导模式**——之前的「引导」只是建卡后她开口一句，藏得太深；而且它应该是一个**独立的模式和预制的提示词**，**不用这么复杂的记忆**

### 建卡向导（独立模式）

- 顶栏「建卡」进入，**独立视图、独立对话流**
- **预制提示词的四步脚本**：名字 → 一句话 → 来历 → 开场白，答完出确认摘要
- **纯前端状态机，不挂记忆管线**——向导里的对话不抽取、不建槽、不进向量库，页面下方一行字明说「这里的对话不会进入任何角色的记忆」
- 确认后：写卡片数据 + 写 identity 人格种子 → 直接进入对话

### 角色编辑 / 删除

- 角色列表每项加「改 / 删」
- **改**：名字、一句话、头像（改 seed 不允许——它是已写入的记忆起点，改了也不生效，诚实一点不暴露这个入口）
- **删**：二次确认 → `POST /v1/wipe?session_id=` 清空该角色全部数据 → 移出列表
- `wipe` 实测：该角色 12 张表全清（episode/persona 各 1），**其他角色不受影响**

### 验证

```
wipe 前 episodes: 1
wipe: episode 1, persona 1（其余 0）
wipe 后 episodes: 0
final1 episodes: 2   ← 别的角色完好
页面 200，测试 15/15
```

## 第十一轮：两路评审 + 重写 app.js

老师：「建卡功能还是不好用，前端也不够好，你 review 一下」。我自己修了三轮「修一个冒一个」，说明**打补丁已经把代码搞成杂交体**——这次不自评，派两路独立评审。

### 评审发现（比自评狠得多）

**代码质量官**：
- 变量体系其实已洗干净（0 未定义、0 重复定义）
- **致命**：`#wizModal` 全项目 **0 处引用**——`wizStart` 从不设 `hidden=false`，**建卡向导 100 行代码从来没被用户看见过**
- boot 里 20 个绑定写**在 `await api` 之后** → 后端不可达时全部不绑，页面半身不遂
- 11 条逻辑漏洞：继续聊后发送键永久禁用、编辑卡串号改到旧卡上、删卡不同步 `CUR_KEY`、头像无配额校验（存不下却零提示）
- 结论：**局部重写**——store 单一状态源 + boot 拆两段 + 向导接线

**视觉审计官**（用 Playwright 拿到真实渲染帧）：
- 「像个做得很干净的**深色开发者工具**，聊天区是它的日志面板」
- 差的三件事：**人名逐条重复**（聊天记录导出感）、**计量挂在她每句话下面**（3.09:1 且破功）、**消息顶对齐**（短对话下方空 280px）
- 8 条必改：打掉 token 行 / 对话底部对齐 / 署名降到每组 / `--dimmer` 提亮（原色在各级深底上 3.89–4.37 全不达 4.5）/ 移动端顶栏不折行 / 打烊态可见 / Esc 与焦点 / 输入区不横贯
- 明确肯定：无玻璃拟态、无霓虹、无渐变文字，三件套一个没犯

### 重写内容（app.js，1049 行）

1. **单一状态源 `store`**：cards / session / card / editing / pendingAvatar / busy / closed / count / debug 全在一个对象里，改完必须 `commit()` 落盘（失败有提示）。之前五份状态各管各的，删卡 bug 就是这么来的
2. **`bindAll()` 前置**：所有事件绑定无条件先跑，网络请求放后面。删掉那句与代码矛盾的注释
3. **向导接线**：`wizStart` 开模态、`wizClose` 绑定、`wizDone` 关闭并进对话
4. **弹层栈**：drawer/cardPop/newModal/setModal/wizModal 统一 `openLayer/closeLayer/closeTopLayer`，Esc 关最上层
5. **署名分组**：`lastSpeaker` 追踪，同人连续消息只在首条出名字
6. **计量默认关闭**：设置里「显示 token 等计量信息」开关，默认不显示
7. **图片上传压缩**：`readImage()` 压到最长边 512 + jpeg 0.8，带大小上限与失败提示
8. **编辑/删除正确接线**：编辑回填写入、删除后同步 `CUR_KEY`/`app.card`/重画历史、不允许删最后一个
9. HTML 补 `role="dialog"` `aria-modal` `aria-labelledby`
