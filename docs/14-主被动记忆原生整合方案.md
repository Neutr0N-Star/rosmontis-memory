## 0 结论先行

1. **主被动不是两套记忆，是三个发起者的同一条记忆管线。** 现在是「两个写入口 + 两套语义 + 一条未接通的 Web 链路」，不是「两个库」。
2. 裂缝分三层：**派生层**（笔记无 fact/超边）、**语义层**（tier/source 多套、四套重要度算法）、**链路层**（Web 的 `/v1/turn` 工具链空转）。
3. 拍板：**方案②「统一对象 + 状态机」**——`episode` 升为唯一 item 表，`state` 为生命周期真值，`tier/source` 降为兼容投影。**已实现**（`core/item.py`、`pipeline.py`、`gate.py`；schema v3 只加列；迁移单事务幂等；见 §2.3）。
4. **整合不接通不算整合**，但要分别验：M6a（系统通道）与 M6b（主动工具通道），见 §3。
5. **主动记忆不能只靠模型举手**：系统整流（结算/整理/做梦）要能产 note 候选；但「自动写成品日记 / 自动改人设」仍是红线——系统只产候选，人设过闸门（C7，与 A3 §7.2 #9 的冲突已登记，见 §7）。
6. 产品主线取 A3：**记忆运行时**（可嵌入库 + 本地守护），MCP 是渠道不是本体；最需警惕 Letta。
7. **整合与产品化是两条时间线**（评审 B9）：整合是周级工程，产品化的身份/鉴权/调度/评测是月级工程，不得混排工期（见 §6）。

### 0.1 部署事实（修订版，替换 v1 的错误表述）

Web 单页路径的准确事实（证据：`web/app.js:374`、`app.py:443-445`、`harness.py:192-220`、`app.py:139-157`、`app.py:159`）：

- `/v1/turn` 的 `llm_call` 恒返回空 `tool_calls` → **Web 路径上五个工具不触发**。
- `Harness(auto_tick=False)` 且前端不调 `/v1/tick` → **自动节拍不跑**。
- 但 Web「下一天」会走 `POST /v1/session/sleep → Harness.sleep`，其中含 `close_session`、条件 `notebook_review`、`dream()` → **review 与做梦在 sleep 时仍会发生**（`should_dream` 需 6h 间隔 + 24h 内 ≥5 条）。
- 库使用者与 `demo/harness_demo.py` 可自接 `llm_callable`，**工具链可用**；外部客户端是否调用主动接口**未确认**。

结论：不是「主动/做梦全不运行」，而是「**Web 路径的工具链与自动节拍不运行**」。M6b 的目标因此限定为「Web `/v1/turn` 工具链接通」，不用「部署」概括全部接入形态。

## 1 核心模型：三类发起者 + 两个派生来源，一个对象

`origin` 枚举（本文明确定义，A2 §3.3 的回填表按此修订）：

| origin | 谁发起 | 写入者 | 回填来源（v2 旧库） |
|---|---|---|---|
| `ingest` | 用户/助手对话 | `write.ingest` → `pipeline.submit` | `source='dialogue'`、`self_reflection`（订正条目）、`manual`/`seed` |
| `tool` | 模型调工具 | `tools.dispatch` → `pipeline.submit` | `source='notebook'` |
| `system` | 系统整流（结算/整理/做梦产物） | `settle`/`review`/`dream` → `pipeline.submit` | `source='dream'`；折叠摘要（现落 `dialogue`/`role='summary'`）在 v3 一并改记为 `summary` |
| `summary` | 折叠摘要 | `forget` 折叠 | 同 `system` 行，按 `role='summary'` 识别 |
| `dream` | 做梦产物，兼容保留 | `dream` | `source='dream'` |

- 三「类」发起者（用户/模型/系统）+ 两个派生来源（summary/dream）。
- **状态机 7 态只覆盖 episode（item）**；fact 走独立生命周期判据（`origin`、`archived`、源自 episode 失效、冷却规则），**不再宣称 fact 与 item 同一状态机**（评审 B4）。
- `Memory.promote` 与 `notebook.promote` 统一经 `gate.decide()`；`PR.can_promote` 保留在 gate 内部。测试矩阵相应改为「经 gate，gate 内部调用 PR」。

## 4 harness 层：能不能用、缺什么、怎么补

| 缺口 | 现状 | 后果 |
|---|---|---|
| 不带对话历史 | `_build_messages` 只发 system + 当轮输入（`harness.py:129-138`） | 指代消解塌；记忆顶替不了上下文窗口 |
| Web 工具链空转 | `app.py:139-157` 恒返回空 `tool_calls` | Web 路径主动记忆不产生（库/demo 可用） |
| 自动节拍不跑 | `auto_tick=False`、前端不调 tick | 自动整理/做梦不发生；sleep 时仍会 review+dream |
| 回调缺元数据 | `llm_callable` 不返回 `usage/finish_reason` | 成本与截断不可观测 |
| 注入长在 turn 里 | `turn` 内拼 system | 宿主自管循环只能复制逻辑 |

补法（优先序）：① 注入抽成纯函数 `context()`（不写库、不超预算）；② 四钩子 `session_start/pre_prompt/post_turn/session_end`（幂等、立即返回）；③ `turn(history, extra_system)`；④ tools 接通（`tool_calls` 解析、`tool_call_id`、usage 落库）；⑤ 节拍移进守护进程（jobs 表 + 单写者队列 + 租约选主）。

## 8 风险与反判据

- **假整合**：接口层统一而派生/淘汰仍分叉 → 反判据：任一入口仍自算 tier 或 salience，即判不成功（含 enrich 后重算）。
- **双写投影失守**：`state` 与 `tier` 被两处代码改 → 一致性校验脚本 + 单一写入口（I11）。
- **迁移事故**：WAL 未 checkpoint、非单事务、非幂等 → 真库修复成本高于收益；W1 备份 + 副本试跑是硬门。
- **判据失真**：用「或」把两条通道合成一条（M6b 必须独立、必须断言 `origin='tool'`）。
- **状态槽污染**（C4 放开后）：留证据链 + 一键回滚。
- **系统越权**：`origin='system'` 直进 persona 必须被 gate 拒绝。
- **工期误导**：整合线与产品化线混排（B9），一律按 §6 两条线报。
