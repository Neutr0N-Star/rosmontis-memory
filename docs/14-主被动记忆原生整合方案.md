## 0 结论先行

1. **主被动不是两套记忆，是三个发起者的同一条记忆管线。** 结构已成：唯一写入点、唯一状态机、单一打分与闸门。
2. 裂缝分三层：**派生层**（笔记无 fact/超边，已收口）、**语义层**（tier/source 多套，v3 收编为 state + origin）、**链路层**（Web 工具链与自动节拍）。
3. 拍板：**方案②「统一对象 + 状态机」**，已实现。
4. **整合不接通不算整合**：分 M6a（系统通道）与 M6b（主动工具通道），见 §3。
5. **主动记忆不能只靠模型举手**：系统整流要能产 note 候选；「自动写成品日记 / 自动改人设」仍是红线（C7）。
6. 产品主线取 A3：**记忆运行时**（可嵌入库 + 本地守护），MCP 是渠道不是本体；最需警惕 Letta。
7. **整合与产品化两条时间线**（B9），不得混排工期（见 §6）。

### 0.1 部署事实（v3，按当前代码逐条核对）

证据全部按当前代码行号列出：

- **Web 工具链已接通**：`/v1/turn` 的 `llm_callable` 由 `make_llm_callable` 构造（`alaya/service/app.py:133-151`）。上游支持原生工具协议时 `tool_calls` **原样透传**（含 `id`/`arguments`/`usage`/`finish_reason`，`alaya/harness.py:398-443`）；上游不支持、无密钥或超时时**安静降级**为空 `tool_calls`（`harness.py:441-443`）。
  → 因此「五个工具是死代码」不再成立：**能不能触发取决于接入的模型是否支持函数调用**，不是路径写死。
- **自动节拍仍不跑**：`Harness(..., auto_tick=False)`（`app.py:149`）；前端只调 `/v1/turn`（`web/app.js:311`）与 `/v1/session/sleep`（`web/app.js:374`），不调 `/v1/tick`。
- **sleep 仍会 review + dream**：`app.py:464-466` → `harness.sleep`（`harness.py:698-718`），含 `close_session`、条件 `notebook_review`、`dream()`；`should_dream` 需 6h 间隔 + 24h 内 ≥5 条。
- 库使用者与 `demo/harness_demo.py` 可自接 `llm_callable`；外部客户端是否调用主动接口**未确认**。

结论：现状是「**自动节拍不跑；工具链已接通但受模型能力约束**」。M6b 的目标限定为「Web `/v1/turn` 在支持工具的模型上产生 `origin='tool'` 条目」。

## 1 核心模型：三类发起者 + 两个派生来源，一个对象

`origin` 枚举（实现见 `alaya/core/item.py:19-24`）：

| origin | 谁发起 | 写入者 | 旧库回填来源（`db.py:236-256`） |
|---|---|---|---|
| `ingest` | 用户/助手对话 | `write.ingest` → `pipeline.submit` | `source` 非 notebook/dream 的对话与订正条目 |
| `tool` | 模型调工具 | `tools.dispatch` → `pipeline.submit` | `source='notebook'` |
| `system` | 系统整流（整理/结算产物） | `notebook.review` 等 → `pipeline.submit` | **旧库无此值**（`system` 自本版起才产生） |
| `summary` | 折叠摘要 | `forget` 折叠 → `pipeline.submit` | 按 `role='summary'` 识别（旧库该行 `source` 落成 `dialogue`，见 A1 #7） |
| `dream` | 做梦产物（兼容保留） | `dream` → `pipeline.submit` | `source='dream'` |

- 三「类」发起者（用户/模型/系统）+ 两个派生来源（summary/dream）。
- **状态机 7 态只覆盖 episode（item）**；fact 走独立生命周期判据（M4b），不宣称同一状态机。
- `Memory.promote` 与 `notebook.promote` 统一经 `gate.decide()`；`PR.can_promote` 保留在 gate 内部。

| 缺口 | 现状 | 后果 |
|---|---|---|
| 不带对话历史 | `_build_messages` 只发 system + 当轮（`harness.py:578`），但 `turn(history=...)` 已支持传入 | 不传历史时指代消解塌 |

## 8 风险与反判据

- **假整合**：任一入口仍自算 tier 或 salience 即判失败（现由扫描断言守）。
- **双写投影失守**：`state` 与 `tier` 被两处代码改 → 一致性校验 + 单一写入口。
- **迁移事故**：WAL 未 checkpoint、非单事务、非幂等 → W1 备份 + 副本试跑是硬门。
- **判据失真**：M6b 必须独立断言 `origin='tool'`，不得用「或」合并通道。
- **文档漂移**：本次两轮评审各抓到一次「文档在说旧代码」——凡引用行号必须在提交时核对（教训记入司历复盘）。
- **工期误导**：整合线与产品化线一律分开报。
