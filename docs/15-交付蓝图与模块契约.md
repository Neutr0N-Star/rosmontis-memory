## 0 第一性原理：记忆系统的三个不可再分的量

1. **记忆是有状态的对象**（不是一条条等距的文本）：它有身份、有生命周期、会失效、会改主意。
2. **回忆是有成本的检索**（不是 top-k）：在有限预算下最大化价值，成本必须可计量。
3. **记住与忘记是同一个过程的两端**（不是两个功能）：写、衰减、归档、折叠由同一套动力学决定。

推论（本文据此立契约）：
- 对象唯一 → `item` 是唯一记忆对象，主/被动只是 `origin`。
- 检索唯一 → **语义场**是唯一检索入口，向量只是点火器。
- 生命周期唯一 → 状态机 + 场动力学是唯一真值。

## 1 语义场（Semantic Field）：把向量库升级成场

### 1.1 定义

场 = 图（结构）+ 向量（相似）+ 时间（衰减）三者的统一表达。

- **节点**：item（episode 派生）与投影物（entity/fact/state_slot/hyperedge）。
- **边**：三类，权重可衰减
  - 结构边：hyperedge 成员关系（现有表，权重 = member.weight）
  - 共现边：同一 episode 中抽出的实体对（稀疏，构建一次）
  - 语义边：向量 kNN（k=8，余弦 > 0.72），**不落库**，查询时按需构建，避免近似索引维护
- **激活**（ACT-R 幂律，替代裸 `access_count` 加成）：
  `A_i(t) = ln( Σ_j (t - t_j)^-0.5 ) + B_i`，`B_i = salience × 2`
- **扩散**（离散版 `D∇²φ`）：`φ ← φ + min(α, 1)·D·L_norm·φ`，迭代 ≤3 次，α = 空间衰减系数
  - 用稀疏乘法实现，复杂度 O(E × iter)，禁止稠密矩阵
- **三空间衰减率**：`identity 0.1 / knowledge 1.0 / operational 3.0`（`memory_field.SPACE_DECAY` 的接线，现在它是死代码）
  - 空间归属：persona/identity 条目 → identity；fact/state/entity → knowledge；会话进度、冷却、工具行为 → operational

### 1.2 检索 = 场点燃 + 预算贪心（四步）

```
1. 点火：query → 种子集 S
   - embedding kNN（top 24）
   - FTS5 关键词（top 24）
   - 实体命中（plan 里解析出的实体，1 跳邻域）
2. 扩散：从 S 出发按 §1.1 迭代，得到候选激活 φ
3. 打分：保留现有 rel/time/salience/graph/emotion 分项（docs/03 §4.3 不动），
   把 access_count 项替换为 A_i(t)，并乘空间衰减系数
4. 打包：现有 L0–L3 四级 + 边际收益贪心 + 绝不超预算（docs/03 §4.3b 不动）
```

**判据**：向量只决定"从哪里点亮"，不直接决定排序。删掉向量路后场仍能工作（FTS+实体点火），只是种子质量下降。

### 1.3 场的内置保护

- 冷启动：无结构边时退化为纯向量/FTS 点火，扩散跳过（不得报错）。
- 空场：种子为空 → 按现有拒答逻辑 abstained，不扩散。
- 环路：迭代次数上限 3，超限截断，不进死循环。
- 可解释：每次检索写入 `retrieval_log` 的 `plan_json` 记 `seeds / iterations / edge_types / phi_top`。

## 2 帕累托优化：质量 vs 成本，两轴都要可测

### 2.1 指标（每项都要有采集脚本，不得手工报数）

| 轴 | 指标 | 采集方式 |
|---|---|---|
| 质量 | 抽取记对率 P、记全率 R、F1 | golden set 人工标注（200 段） |
| 质量 | 召回 nDCG@10 / 时序 / 多跳 / 更新 / 偏好 四类准确率 | 题集 + 判定脚本 |
| 质量 | 拒答误召率、漏召率 | 标注集 + 阈值扫描 |
| 质量 | 人格漂移率（200 轮 identity 不变） | 长程脚本 |
| 质量 | 场增益：扩散带来的新增相关命中比例 | 对比「关扩散 vs 开扩散」 |
| 成本 | 注入 token、检索延迟 p50/p95、写入延迟、LLM 调用次数、单会话成本 | benchmark 脚本落 JSON |

### 2.2 帕累托纪律

- **基线纪律**：所有基线只在**库副本**上跑，记录副本 `sha256` 与固定 `now/as_of`；`Memory.recall` 默认写库（`retrieval_log`、`access_count`、`cooldown`），因此基线必须显式用副本或只读模式（`write_log=False, touch=False`）。**禁止「对真库只读回放」这种说法。**
- **支配判定**：配置 B 支配 A，当且仅当 B 在所有质量指标 ≥ A，且所有成本指标 ≤ A，且至少一项严格更优。
- **改动准入**：任何影响检索/抽取/预算的改动，必须给出「改动前后在同一基准集上的支配关系」。做不到就说明改动不可评估，不许合。
- **前沿报告**：`bench/report.md` 由脚本生成，列 6–10 个配置的帕累托前沿（扩散强度 × 深度 × 预算）。
- **不得**用「感觉更好」代替数字；**不得**引用别家 benchmark 数字（未跑自己的）。
