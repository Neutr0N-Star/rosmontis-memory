## 0 一页结论

**系统骨架是好的，短板集中在一处硬瓶颈、一处事故风险、一处入门门槛。**

1. **性能**：向量扫描吃掉 97% 的检索延迟——20k 条 p50 732ms、100k 条 3.0s；其余三路（FTS/图/场）加起来不到 1/10。**不解决它，产品就只能跑几万条以内。**
2. **事故风险**：旧库（真库当前 `user_version=2`）**首次打开就会原地迁移**，无备份、无只读、无预演；失败直接 raise。这是唯一可能毁数据的 P0。
3. **入门门槛**：README 有 18 处过期（没有 `alaya.open`、没有四钩子、预算/测试数/异步说法全错），`pip install -e .` 之前根本不存在（本轮已补 pyproject）。
4. **学理**：扩散公式文档写的版本**会发散**（实现另写了对的版本）；「三空间 0.1/1/3」「B=2·salience」「θ=0.18」都没有依据，属待标定；`docs/10` 要求的「情绪不再直接提权」在代码里没落地（祥林嫂放大器还在）。
5. **接口**：库层 `Handle` 与 HTTP 是两套生命周期、两套保证（HTTP `/v1/context` 会写库且超预算，本轮已修）；「所有方法幂等」口径不明（`settle` 重跑会二次改写 salience）。

**最该先做的五件**：内存矩阵缓存（2d）→ 迁移安全开关（2d）→ README+guide 收口（2d）→ settle 幂等口径 + HTTP/库同源（2d）→ 参数标定基础设施（3d）。

## 1 性能（B1，实测量级）

100k 档 p50（20k / 1k 括注）：

| 路径 | 100k | 说明 |
|---|---|---|
| `Memory.forget` | **16.15s**（2.84s / 5.1ms） | 32,161 条 SQL：每条冷条目一次超边 N+1 + 逐条状态机；批量化实测可到 1.0–1.5s |
| `Memory.recall` | **3.24s**（0.83s / 0.046s） | dense 2.67–2.82s 占 85–87% |
| `Memory.close_session` | 0.36s（25ms / 3.5ms） | 默认 `auto_forget=True` 时末尾再叠一次 forget（20k 实测 2.65s） |
| `ingest`/accept | 97ms（—/—） | 几乎全花在 `MAX(seq)` 全表扫（加覆盖索引后 0.004ms）；默认写事实还内陆衰减 +0.39–0.85s |

| 编号 | 优化 | 现状 → 预期 | 成本 | 状态 |
|---|---|---|---|---|
| P-0 | **dense 取数三连**：`(session_id,t_ingest DESC)` 索引 + 去掉 `(?='*' OR col=?)` 反模式 + 窗口可配 | 100k dense 2.78s → 约 100ms（-96%）；20k 698ms → 100–120ms | 0.5d | **本轮已实施**：实测 20k dense 682→472ms（-31%），窗口调 10000→287ms、5000→118ms（见下）；默认仍 20000 |
| P-0b | `MAX(seq)` 覆盖索引 `(session_id,seq DESC)` | 103ms → 0.004ms | 0.2d | **本轮已实施** |
| P-1 | `forget` 批量化（超边成员一次 joins 取、状态转移批量、去 N+1） | 100k 16.15s → 1.0–1.5s | 3d | P1 |
| P-2 | 热窗口向量矩阵常驻（5000–20000 条 float32，20–82MB） | dense 再降到 2–5ms | 3–5d | P1（风险：写失效广播，enrich/dream/forget 都改向量） |
| P-3 | 窗口默认值标定（2000/5000/10000/20000 扫 bench） | 20k 实测：20000→472ms、10000→287ms、5000→118ms | 1d | **待拍板**：窗口越小越快，但会牺牲久远记忆（时序题最敏感）；bench 数据集只有 400 条，测不出窗口效应，必须上真实语料 |
| P-4 | 读路径零写（`retrieval_log`+`_touch` 异步批量） | 单次 recall 少 1–2 笔写事务 | 1d | P1 |
| P-5 | `states` 查询随规模线性（100k 97ms） | 复合索引 + 批量预取 → <10ms | 0.5d | P1 |

**实测已否掉**：调大 `cache_size` 无收益；int8 量化在 numpy 下反而慢 11 倍；ANN 在当前规模不划算。
**判据**：任何一条上线前必须给 `bench/report.md` 的新旧支配关系；P-0 的验收已达成（见 §7）。
