# 接入形态与接口方案（v2 · 开源本地部署）

> 状态：v2 · CEO 已定（2026-10-19）：**开源项目**；别人 clone/拉取到本地，接自己的前端；**前端不在产品内**；优先本地接口，按业界通行做法做稳定与通用。
> v1 曾把 MCP 列为渠道，本版**移出主线**（理由见 §2）。
> 本文回答：对外暴露什么接口、承诺什么、怎么保证稳定通用、分几期。

---

## 0 一句话定位

**Alaya = 一个可以 pip 安装、也可以一条命令起在本地的「记忆后端」。** 别人把它拉下来，用自己的前端（Web/桌面/移动/自研）通过 HTTP 接口接上；Python 项目也可以直接 import 当库用。

前端、提示词、UI 交互一律归使用方；本仓库只提供「记忆」这一层的引擎与接口。

---

## 1 对外只有两个面（这才是"通用"的定义）

| 面 | 形态 | 谁用 | 稳定性承诺 |
|---|---|---|---|
| **HTTP API（主线）** | `alaya serve` 起在 `127.0.0.1:8770`，`/v1/*` REST + OpenAPI | 任何语言的前端/后端（Web、Electron、桌面、移动） | **v1 冻结**，破坏性改动升 v2 |
| **Python 库（副线）** | `pip install alaya-memory` → `alaya.open()` + `Handle` | Python agent / 数据脚本 | **v1 冻结** |

MCP、gRPC、WebSocket 等**不进 v1 主线**（见 §2 与 §6）。

---

## 2 为什么砍掉 MCP（基于本项目定位的判断）

- MCP 的消费者是「agent 宿主」（Claude Code / Cursor 这类），不是「人的前端」。本项目目标是让别人接**自己的前端**，MCP 帮不上这件事。
- MCP 拿不到「每轮自动注入 + 会话结算」，只能暴露检索工具，价值打五六折；为它做的适配反而是负债。
- 工具层（`tools.py` 五个工具）已经在，将来要做 MCP 只是加一层 100–150 行的映射，**随时可以补，不占现在的位置**。放进 backlog。

## 4 对外接口面（v1 冻结候选）

**会话与对话**
- `POST /v1/session`（开/取会话，返回 `session_id` 与人格块摘要）
- `POST /v1/turn`（整段回复，同步）
- `GET  /v1/turn/stream`（SSE 流式：`meta` → `delta*` → `done`，见 §5）
- `POST /v1/session/sleep`（结算：峰终 + 整理 + 可能做梦）
- `POST /v1/observe`（宿主自己管循环时，回写用户/助手文本）

**读**
- `POST /v1/context`（纯函数：人格 + 常驻 + 检索，绝不写库、绝不超预算）
- `GET  /v1/state/{scope}`、`GET /v1/timeline/{entity_id}`、`GET /v1/episodes`、`GET /v1/items/{id}/state`
- `GET  /v1/stats`、`GET /v1/healthz`、`GET /v1/readyz`

**管理（本地 CLI / 管理员）**
- `POST /v1/forget/run`、`POST /v1/backup`、`POST /v1/restore`、`POST /v1/wipe`
- 说明：管理面默认只在 loopback 可用；若绑到公网必须开 token（M2）。

**不做**：UI 资源、prompt 模板、模型代理（用宿主自己的模型）。

## 5 流式接口约定（前端最关心的那条）

```
GET /v1/turn/stream?session_id=u1&text=...
Content-Type: text/event-stream

event: meta      data: {"memory_tokens":183,"persona_chars":420,"tools_called":[],"abstained":false}
event: delta     data: {"text":"那就"}        # 0..N 次
event: tool      data: {"name":"alaya_remember","ok":true}
event: done      data: {"reply":"...","latency_ms":820,"tokens":183}
```

- 不支持流式的上游模型：服务端把整段回复切成 1–2 段 `delta`，**接口形态不退化**。
- 断连即取消：客户端断开后不再写库（`done` 之前不落 assistant 记忆）。
- 每条 `event` 一行 JSON，前端 `EventSource` 或 `fetch` 流式读取都能用。

## 7 明确不做

- 不做前端（任何界面）；前端选型不进入本仓库。
- 不做 prompt 模板与说话风格。
- 不做多 agent 编排。
- 不默认对外网暴露、不默认多租户（M2 才做）。
