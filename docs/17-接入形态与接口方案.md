# 接入形态与接口方案

> 定位：Alaya 是开源、本地部署的**记忆后端**。别人 clone 到本机，用自己的前端通过接口接上；前端不在本仓库内。
> 本文 owner：对外接口面、接入形态、宿主契约、版本承诺。接口的内部实现契约见 [15-交付蓝图与模块契约](15-交付蓝图与模块契约.md)；主被动整合口径见 [14](14-主被动记忆原生整合方案.md)。

---

## 0 一句话定位

**Alaya = 一个可以 pip 安装、也可以一条命令起在本地的「记忆后端」。** 任何语言的前端（Web/桌面/移动/自研）通过 HTTP 接上；Python 项目可以直接 import 当库用。

提示词、说话风格、UI 交互一律归使用方；本仓库只提供「记忆」这一层。

---

## 1 对外只有两个面

| 面 | 形态 | 谁用 | 稳定性承诺 |
|---|---|---|---|
| **HTTP API（主线）** | `alaya serve` 起在 `127.0.0.1:8770`，`/v1/*` REST + OpenAPI | 任何语言的前端/后端（Web、Electron、桌面、移动） | **v1 冻结**，破坏性改动升 v2 |
| **Python 库（副线）** | `pip install alaya-memory` → `alaya.open()` + `Handle` | Python agent / 数据脚本 | **v1 冻结** |

MCP、gRPC、WebSocket 不进 v1 主线（§2、§9）。

---

## 2 为什么 MCP 不在主线

MCP 的消费者是 agent 宿主（Claude Code / Cursor 这类），不是人的前端。它的协议里没有「每轮注入」和「会话结算」的钩子，因此接入方只能拿到检索工具，拿不到人格与状态槽的连续注入——那正是本项目的两条主要差异点。

工具层（`tools.py` 的五个工具）是现成的，将来要接 MCP 只需加一层 100–150 行的协议映射，不构成架构负担。列入 backlog（§9）。

---

## 3 宿主契约：接入能拿到多少价值，取决于这四条

记忆系统的价值一半在**时序**上：每轮注入、会话边界、维护节拍。时序必须由宿主配合，接口本身替代不了。

### 3.1 四条必须项

| # | 宿主必须保证 | 对应能力 | 漏了会怎样 |
|---|---|---|---|
| 1 | 模型调用**前**，把 `system_prefix + memory_text` 放进 system | `build_context(pure=True)` / `POST /v1/context` | 降级成检索库，人格与状态槽失效 |
| 2 | 每轮 **user 与 assistant 两条**都回写 | `ingest_async` / `POST /v1/episodes` / `POST /v1/observe` | 被动抽取、峰终结算、做梦材料缺一半 |
| 3 | 把五个工具 schema 交给模型并执行返回结果 | `dispatch` / `/v1/recall` 等 | 主动记忆只剩系统通道 |
| 4 | 有地方按时间敲维护 | `Memory.tick` / `POST /v1/tick` / `alaya daemon` | 整理与做梦永不发生 |

第 2 条最常被漏：多数接入只考虑「怎么把记忆喂进去」，忘了「怎么把对话记下来」。只记用户一侧，等于记忆残一半。

### 3.2 一条否决项

**宿主不能改写或重排注入内容。** 典型反例：前端自带 world info / 全局提示词槽位，覆盖或压缩 system 消息；成品编排器自行重排 system。被改写的注入等于没注入。

### 3.3 分档判定：五问量一个候选宿主

1. 模型请求前，有没有一个可修改的「拼 prompt」位置？
2. 每轮的 user 文本与 assistant 文本能不能拿到？
3. 请求体能不能塞 `tools`，或能不能挂插件？
4. 有没有定时器或后台任务的落脚点？
5. 它的身份键是「人」还是「会话」？

| 满足情况 | 档位 | 能拿到的价值 |
|---|---|---|
| 缺第 1 条 | 不成立 | 只能当外部检索工具，不构成接入 |
| 1 + 2 | 被动记忆 | 抽取、状态、召回、遗忘 |
| 1 + 2 + 3 | 主动记忆（工具通道） | `origin='tool'` 落库 |
| 1 + 2 + 3 + 4 | 完整 | 含 `origin='system'` 整流与 `origin='dream'` |
| 第 5 问答错 | 会失忆 | 记忆挂在会话上，换场景即丢人 |

第 5 条对应 `space/conversation` 两层隔离（§9 M2）；在只有 `session_id` 的现状下，跨场景共享需要调用方自行约定同一个 `session_id`。

## 4 编排层的位置：谁是契约本体

`harness.py` 里有两类东西，定位不同：

| 成分 | 位置 | 定位 |
|---|---|---|
| `build_context` / `render_system` / `fit_memory_text` | 模块级函数 | **契约本体**：注入、预算硬闸、必不超预算 |
| `normalize_tool_calls` / `parse_*_response` / `chat_with_tools` / `make_llm_callable` | 模块级函数 | 协议适配工具，可复用 |
| `dispatch`（`tools.py`） | 模块级函数 | **契约本体**：工具执行 |
| `Harness` 类（`wake/turn/sleep/tick`） | 类 | **参考编排器**：可整体替换，宿主自管循环时不必使用 |

判断依据很直接：服务层的 `/v1/context` 与公共 API 的 `Handle.context` 都直接调模块级 `build_context`，不经过类。类只做编排与转发，没有记忆算法。

宿主替换编排器时，下面这些决定要么继承、要么重新回答（都踩过坑）：

1. 空回复必须抛错，不能当正常回复写进记忆；
2. 工具轮上限 3，超限后带已有结果再收一次尾；
3. 工具失败原因必须回灌给模型，不能吞；
4. 纯函数注入时静音检索日志，不污染访问计数；
5. 预算硬闸按整行丢弃，绝不截半句；
6. 流式断连不写半截 assistant 记忆；
7. 结算三步各自隔离，峰终失败不能连累做梦。

## 5 业界通行做法：本地后端的 12 条自查

| # | 事项 | 业界惯例 | 状态 |
|---|---|---|---|
| 1 | **版本化路径** | `/v1/...`，破坏性改动升版本 | ✅ 冻结面见 §6 |
| 2 | **OpenAPI 契约** | `/openapi.json` + 仓库内快照 | ✅ 48 路径，CI diff |
| 3 | **统一错误信封** | `{ok,data,error{code,retryable,message}}` | ✅ 5xx 默认 `retryable=true` |
| 4 | **只绑本机** | 默认 `127.0.0.1`，不默认暴露公网 | ✅ 服务与 Docker 都绑本机 |
| 5 | **流式输出** | SSE `text/event-stream` | ✅ `POST /v1/turn/stream` |
| 6 | **CORS 可配** | 默认本机来源，可显式配置 | ✅ `ALAYA_CORS_ORIGINS` |
| 7 | **健康与就绪** | `/healthz`、`/readyz` | ✅ 含库版本、向量模式、待回算 |
| 8 | **优雅关停** | SIGTERM 收尾在途任务 | ✅ lifespan join，已实测 |
| 9 | **幂等与重试** | 写接口幂等键；错误标 retryable | ✅ `Idempotency-Key`（24h 回放） |
| 10 | **分页与过滤** | `limit/offset/cursor` 一致 | ⚠️ 部分接口有，未统一（M2） |
| 11 | **分发与运行** | pip 包、Docker、一条命令 | ✅ wheel + Dockerfile + compose |
| 12 | **许可与安全** | LICENSE、密钥不落库 | ✅ MIT；密钥走环境变量 |

## 6 对外接口面（v1 冻结）

**会话与对话**
- `POST /v1/session/wake`（开会话：播种、载入人格）
- `POST /v1/session/sleep`（关会话：结算 + 整理 + 可能做梦）
- `POST /v1/turn`（整段回复）｜`POST /v1/turn/stream`（SSE，契约见 §7）
- `POST /v1/observe`（宿主自管循环时回写一来一回，支持幂等键）
- `POST /v1/settle`（立即返回 job_id，后台结算）｜`GET /v1/jobs`（任务积压）

**读**
- `POST /v1/context`（纯函数：人格 + 常驻 + 检索；不写库、不超预算）
- `GET /v1/state/{scope}`、`GET /v1/timeline/{entity_id}`、`GET /v1/episodes`、`GET /v1/items/{id}/state`
- `POST /v1/recall`（检索，返回证据包与打分明细）
- `GET /v1/stats`、`GET /v1/healthz`、`GET /v1/readyz`

**维护与管理（本地 CLI 或 loopback）**
- `POST /v1/forget/run`、`POST /v1/tick`、`POST /v1/wipe`
- 备份/恢复走 CLI：`alaya backup`（先 WAL checkpoint 再复制，输出 sha256）；恢复停服务后替换文件。
- 管理面默认只在 loopback 可用；绑定公网必须加 token（M2）。

**不做**：UI 资源、prompt 模板、模型代理。

## 7 流式接口约定

```
POST /v1/turn/stream
Content-Type: application/json      body: {"session_id":"u1","text":"..."}
Accept: text/event-stream

event: meta    data: {"memory_tokens":183,"persona_chars":420,"abstained":false}
event: tool    data: {"tool":"alaya_remember","ok":true}     # 0..N 次
event: delta   data: {"text":"那就"}                          # 0..N 次
event: done    data: {"reply":"...","latency_ms":820,"tokens":183}
```

- 上游模型不支持 token 流时，服务端按段切分，**接口形态不退化**。
- 断连即取消：`done` 之前不写 assistant 记忆。
- 每条 `event` 一行 JSON，`fetch` 流式读取即可；不需要 `EventSource`（需要 POST body）。

## 8 向量通道与模型资产

向量检索是核心能力，不是可降级外挂。接入方需要知道三件事：

### 8.1 通道

| `ALAYA_EMBED` | 状态 | 形态 | 适用 | 说明 |
|---|---|---|---|---|
| `local` | **待交付** | 本地 ONNX 进程内推理 | 无 Ollama、无 API key 的机器 | 代码侧无推理实现；配置即启动报错（v1.1.1 起不再静默降级为 hash） |
| `openai` | **待交付** | OpenAI 兼容 `/v1/embeddings` | 已有对话 key 且通道支持 embeddings | 同上；配置即启动报错 |
| `ollama` | 可用 | 本地 Ollama 服务 | 已装 Ollama | 默认通道 |
| `hash` | 可用 | 确定性哈希伪向量 | **仅测试/离线演示** | 余弦无语义意义；检索会跳过 rel 门 |

> **落地状态（v1.1.1 校正）**：断路器、向量身份（schema v4）、按身份回算与 `/readyz` 的 `vector_mode` 已上线。`local` 与 `openai` **不在 v1.1.0 的交付内容里**——它们原计划随 v1.1 落地但未实现，v1.1.1 起改为「配置未实现通道即启动失败」，避免"以为在跑语义检索、实际是 hash 且全库不落向量"。`alaya models install` 的下载能力与推理通道是两条独立的线，前者已交付、后者未开始。

`/readyz` 返回 `vector_mode`（`semantic` / `degraded` / `none`）、模型名、维度、待回算条目数。任何时刻都能判断「现在是不是真在跑向量检索」。

### 8.2 模型是独立可下载资产

模型不进 wheel。`alaya models install <name>` 下载到 `~/.alaya/models/`（或 `ALAYA_MODEL_DIR`），带断点续传、3 次重试、SHA-256 校验；校验失败保留旧模型。可用 `--mirror` 或 `ALAYA_MODEL_MIRROR` 换镜像。`list / where / verify / remove` 覆盖日常运维。

### 8.3 向量身份与回算

写入时记录 `embed_model` / `embed_dim`；检索只比较同身份向量（旧库两列为 NULL 视为未知，仍可用）。降级期写入的条目向量为空，恢复后由 `embed_backfill` 任务补齐——降级可以发生，但不能不可逆。详见 [15 §3.6](15-交付蓝图与模块契约.md)。

## 10 明确不做

- 不做前端（任何界面）；前端选型不进入本仓库。
- 不做 prompt 模板与说话风格。
- 不做多 agent 编排。
- 不默认对外网暴露、不默认多租户（M2 才做）。
