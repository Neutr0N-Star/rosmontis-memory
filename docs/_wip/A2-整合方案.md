# A2 · 主动记忆与被动记忆的原生整合方案

> 契约级设计，不含实现代码。基线：schema v2（`PRAGMA user_version=2`）、`tests/test_all.py` 15 项、真实库 alaya.db 1.7MB（WAL 4.3MB 未 checkpoint）。
> 证据来源：只读代码勘察 + 对 alaya.db 的只读连接查询（`mode=ro`，未写入、未 checkpoint、未装依赖）。
> **拍板：方案②「统一对象 + 状态机」。** 理由见 §5，代价与需 CEO 决定的取舍见 §9。

## 0 目标与判据

### 0.1 一句话目标

同一份记忆对象，差别只在谁发起写入：主动（模型调工具）与被动（系统抽取）是同一条 item 的两种产生方式，共用同一写入管线、同一状态机、同一套打分/衰减/检索/淘汰；「谁发起」只记成 `origin` 字段，不改变对象行为。

### 0.2 什么算整合成功（M1–M5）

| 编号 | 判据 | 怎么测（可执行） |
|---|---|---|
| M1 | **写入单点**：不存在绕过统一管线的 `episode`/`fact`/`state_slot` 写入 | 代码：`INSERT INTO episode` 只出现在管线模块；运行：每次写入必有 1 条 `item_state_log` |
| M2 | **结构投影同构**：同一内容经两入口写，结构投影口径相同（允许异步延迟，不允许口径不同） | 双临时库对照：note 的 what 文本 vs 等价对话文本，`enrich` 后 fact/state 集合 diff 为空（顺序无关） |
| M3 | **打分单点**：salience/emotion/rel/time/access 各只有一份实现 | 同字段输入两入口 salience 差 = 0；改一次系数，两入口同时变 |
| M4 | **生命周期单点**：retention/归档/折叠/冷却/弃置一份实现，且对 episode 与 fact 都有定义 | 同 `t_event/salience/access_count` 的主动/被动条目：retention 差 < 1e-9，归档时刻相同 |
| M5 | **闸门单点**：升格/降格/撤回/静音经同一 `gate.decide()` | 穷举 `(origin,state,memory_type,author,confirmed,target)` 只有一张判定表；改一个常量两入口同时变 |

### 0.3 怎么测

- 回归硬门：`python tests/test_all.py` 必须 15/15。
- 新增：`tests/test_integration_items.py`，用两个临时库（不碰真库）对跑主动/被动两条入口，断言 M2–M4 的数值等价。
- 只读回放：改造前后各对真库跑固定 20 条查询的 recall top-10，导 JSON 比对，一致率 ≥95%（基线在 P0 冻结）。
- 代码断言：`episode`/`fact` 的 INSERT 调用点计数、`salience` 计算函数引用计数。
- **反判据**：任一入口仍自算 tier 或自算 salience，即判整合不成功——不看「功能能跑」。

### 1.1 真实库基线（迁移风险的底数）

- 规模：episode 182（dialogue 180 + dream 2）、fact 28（active 25 / invalidated 3）、开放 state_slot 5、entity 34、hyperedge 16、page 11、persona 36、retrieval_log 104、dream_log 2、tombstone 0。
- **主动层零数据**：`source='notebook'` 0 条、`tier='inbox'` 0 条、`tier='resident'/'important'` 0 条、`notebook_promotion` 0 条 → 整合的数据迁移量≈0，成本在代码与测试，不在搬数据。
- 测试残留：1 条 `t_event=1e18`、session id `'../../etc/passwd'`、2 行 `tier='dream'`（不在 PR.TIERS 内）→ 迁移脚本必须容错，**不许**借迁移加枚举 CHECK 强约束。
- WAL 未 checkpoint → 任何备份/迁移前先 `PRAGMA wal_checkpoint(TRUNCATE)` 再复制，否则备份不一致。

## 2 方案① 薄统一（共享管线 + 双入口适配层，schema 不动）

**对象与契约**：新增进程内 `MemoryItem`（不是表，字段=现有 episode 列 + 四段 segments）；新增 `pipeline.commit(item)` 作为唯一 `INSERT INTO episode` 处；新增 `gate.decide(item, action)`；salience 收口为 `score.salience_of()`。两入口只负责「造 item」：被动适配层做抽取并填 fact/state 候选，主动适配层把四段拼 body；tier 由 gate 算，`meta_json` 记 `origin`。

**schema 变更**：无。`inbox` 只是新增常量，TEXT 字段直接容纳。

**API/工具契约**：5 个工具名与参数不变；`alaya_remember` 返回值把 `layer` 改称 `state`（保留 `layer` 一版兼容）；`alaya_promote` 仍只写 persona。HTTP 不变。

**迁移路径**：无 DDL、无数据迁移；旧库直接跑。回滚 = 回滚代码，库无痕。

**harness 影响**：无签名变化；`turn` 的工具结果多一个 `state` 字段，`_stringify` 自然带出。

**成本 / 风险 / 失败条件**：3–5 人日，改 5 文件 + 2 新模块 + 4 项新测试。风险低。**会在这些条件下失败**：(a) 一旦要求「主动条目也能更新状态槽」——她说「我搬去城东了」应更新 city，就必须破「schema 不动」；(b) 一旦要求 fact 也衰减/静默/归档——fact 缺字段，必然破界；(c) 15 项测试扩一条「fact 也进淘汰」即崩。它只达成 M1/M3/M5，**M2/M4 不达成**，所以是「接口整合」不是「对象整合」。

## 3 方案② 统一对象（MemoryItem + 状态机，schema v3 小迁移）

### 3.1 对象与契约

`episode` 升级为**唯一 item 表**（不新建 item 表，避免搬 182 行）。新增 `state` 为生命周期真值，`tier`/`source` 降级为**对外兼容投影**（双写至少一个版本）。`MemoryItem` = episode 行 + 派生自 `item_state_log` 的状态历史。fact/state_slot/page/persona 仍是投影物，但它们的生命周期规则写进同一张表、由同一 dispatcher 执行。

### 3.2 状态机（唯一判定表）

状态集（7）：`inbox / note / important / resident / archived / muted / dream`。`important` 与 `dream` 是兼容态（沿用旧 tier 值），后续可拆成「优先级标记」。

| 当前态 | 动作 | 目标态 | 执行者 | 召回可见 |
|---|---|---|---|---|
| — | 被动 ingest | note（gate 可给 resident） | 系统 | 是 |
| — | 主动 remember（无第二层） | inbox | 工具 | **否**（C2 默认，见 §9） |
| — | 主动 remember（有第二层） | note | 工具 | 是 |
| inbox | review：同主题合并命中 | note | tick/sleep | 是 |
| inbox | review：提炼不出 | archived | tick/sleep | 否 |
| note | promote_resident | resident | gate | 是（每轮注入） |
| note | promote_persona / promote_page | note（+persona/page 行 +log） | gate | 是 |
| resident | demote | note | gate | 是 |
| 任意 | skip | muted | 工具 | 否 |
| 任意非 resident | forget 衰减越阈 | archived | 节拍 | 否 |
| dream | 抽象产物经 gate | note/resident | gate | 是 |
| 任意 | revise | 旧条留在原态 + `superseded_by` 指针 | 工具 | 否（可显式查） |

`promote_resident` 与 `promote_persona/page` 是**两种不同动作**——这正是 D4 的根因，必须显式区分。所有转移写 `item_state_log`（唯一审计，吸收 `notebook_promotion`）。

### 3.3 schema v3（只加列/加表，不改不删不重命名）

| 表 | 新增 | 回填规则 |
|---|---|---|
| episode | `origin TEXT`、`state TEXT`、`state_at REAL`、`gate_version TEXT` | origin：notebook→tool，dialogue/self_reflection/manual/seed→ingest，dream→dream，summary→summary。state：muted=1→muted；archived=1→archived；tier=resident/important/inbox/dream 依次映射；其余 retrieval→note |
| fact | `origin TEXT`、`archived INTEGER DEFAULT 0` | origin：有 `source_episode` 且该 episode origin=tool→tool，否则 ingest |
| 新表 | `item_state_log(id, item_id, from_state, to_state, action, target, reason, gate_json, at, actor)` | 存量每条补 1 条 backfill 记录 |
| 索引 | `idx_ep_state(session_id,state,muted)`、`idx_log_item(item_id,at)` | — |

`notebook_promotion` 保留只读一个版本，不再写入。

### 3.4 闸门（M5 的落点）

`gate.decide()` 内部**保留** `PR.can_promote`（tool_behavior 禁 resident、情绪需 confirmed——测试依赖它，见 §7.3），叠加 notebook 的频率（≤2/会话）/幅度（≤200 字）/来源（必须来自笔记），并预留 docs/11 的复现（≥2 次梦）+时效（≥3 天）为**默认关闭的开关**（C1）。返回 `{ok, from, to, target, reason, gate_version}`，失败必须带原因（沿用 docs/12 §4 的契约）。

### 3.5 API/工具契约

- `alaya_remember`：参数不变；返回 `{ok,id,state,...}`（`layer` 保留一版）。
- `alaya_promote`：增可选 `target: resident|persona|page`，默认 `persona`（向后兼容）；返回统一 `{ok,from,to,reason}`。
- `alaya_skip`：改走 `state→muted`，并**同时支持 fact**（现实现只 UPDATE episode，`tools.py:189-193`）。
- HTTP：新增 `GET/POST /v1/items/{id}/state` 与 `/v1/items/{id}/transition`（运维/测试用）；`/v1/notebook/*`、`/v1/promote` 保留为别名；错误统一 `{ok,error:{code,retryable}}`。

### 3.6 迁移与回滚路径

- 迁移：`db.py` 的 `SCHEMA_VERSION=3`，`_migrate` 沿用现有「逐版本只加列」机制；**单事务**：加列→回填→建表→补 backfill log→写 `user_version=3`。幂等：只有 `user_version<3` 才跑；失败 ROLLBACK 保持 v2。
- 回滚：**只回代码，不删列**。旧代码（v2）不读未知列、继续写 `tier/source`，在 v3 库上行为与 v2 等价；但回滚窗口内新列的 `state` 会陈旧 → 二次升级必须按 `state_at`/`origin IS NULL` 重新回填（脚本幂等）。不提供 `DROP COLUMN` 回滚（SQLite 版本依赖、有数据风险）。
- 15 项测试：全部用临时库从 `schema.sql` 建 v3 → 通过；真库另跑只读回放（§0.3）与 §7.3 矩阵。

### 3.7 harness 影响

`wake/turn/sleep/tick` 签名不变。`turn`：工具结果多 `state/from/to`，`_stringify` 直接展示；`MAX_TOOL_ROUNDS=3` 不动。`tick`：增加 forget 步骤；`sleep` 与 `tick` 的整理合并为单一 `settle()`，用 meta 锁去重（同一 inbox 12h 内只 review 一次）。`wake` 的 inbox 计数改读 `state='inbox'`。

### 3.8 成本 / 风险 / 失败条件

13–16 人日；2 个新模块（`item`、`gate`）+ 1 次迁移；改约 10 个文件；8–10 项新测试。**会在这些条件下失败**：(a) 双写投影纪律失守（`state` 与 `tier` 由不同代码改）→ 两个真相回来，必须靠「写路径单一入口 + 校验脚本」防；(b) 把异步富化当可省 → 主动条目永远没有结构投影，退化成方案①；(c) 迁移未 checkpoint / 非单事务 / 非幂等 → 真库修复成本超过收益；(d) 未来要求「笔记」有独立检索通道或独立前端字段 → 单表承载不了语义差异，需要再拆。

## 4 方案③ 事件/场驱动（写入总线 + 激活场统一调度）

**对象与契约**：一切写入 = 一条 append-only `MemoryEvent`，由总线投给投影器（产 fact/state/entity/edge/note）与激活场；检索 = 场点火 + 预算贪心；淘汰 = 场势衰减越阈。对象是节点、类型是势函数，「层」不再存在。

**schema 变更**：大。新增 `memory_event`、`memory_node`、`memory_node_edge`；现有 5 张表降为投影物（双写期并存）；存量 182+28+34+16+5 全量搬入节点表，回滚需双份（体积≈2×）。

**API/工具**：工具语义改为「提交事件」，返回 `accepted/queued`，不再同步回「写了几条事实」；`facts()`/`state_snapshot(as_of)` 需在节点模型上重建 shim → shim 本身成为第二套真相。

**迁移路径**：三阶段（写事件+写旧表 → 对账 parity → 切读）；回滚需要双份数据与回放脚本。15 项测试约 6 项依赖旧语义（预算/拒答/时间旅行/幂等），需改写。

**harness 影响**：`tick` 变成总线心跳，`wake/sleep` 映射点火/固结；工具循环可能变成「先收后算」，回复时不知道写入结果 → 直接违背 docs/12 §4「失败原因必须回传」。

**成本 / 风险 / 失败条件**：20–30 人日，风险最高。**会在这些条件下失败**：(a) 单一激活场无法同时表达 docs/09 的四种消亡方式（速记消耗品/笔记资产/沉淀结论/人设身份）→ 一锅打分，召回质量回退；(b) 双写对账不齐 → 检索缺条；(c) 兼容 shim 成为第三套真相；(d) 升级后无法按类型查表定位问题，运维与验收成本失控。

### 5.2 拍板：方案②

只有②同时达成 M1–M5，且与 15 项测试、真实库、harness 签名都相容：迁移是**加列级**（无数据搬运，主动层真库零行），回滚只回代码，状态机把「谁发起」降级为一个字段。①的整合只到接口层，M2/M4 永远不达标；③的收益（更纯的「一层」）抵不过它的迁移与兼容成本，且与 docs/09 的分层消亡理论直接冲突。

### 5.3 为什么不是①/③

- 不选①：它把「整合」定义成适配层。真实分叉点在**结构投影**（D1）与**淘汰**（D5），这两处①碰不到；一年后必然再开一次整合。
- 不选③：它为「一层」付出的代价是双写对账、shim、测试重写和可调试性；而本项目当前主动层零数据、真实用户仅 182 条 episode，③的规模收益（十万级）用不上。等 P5 完成、主动条目过千再做场化，才是合理时机。

## 7 迁移与回滚手册

### 7.1 迁移前置（P3 执行前）

1. 停 harness / web / demo，确认无后台 enrich 线程。
2. `PRAGMA wal_checkpoint(TRUNCATE)`；复制 `alaya.db`；记录 sha256 与 `user_version`。
3. 在备份副本上试跑迁移 + I9/I10 + 只读回放，通过后再对真库执行。
4. 迁移后跑 `PRAGMA integrity_check`、15 项测试、M2–M4 对照。

### 7.2 回滚

- 代码回退到 v2；**数据库保留 v3 列**（旧代码忽略未知列，继续写 `tier/source`）。
- 回滚窗口内不依赖 `state` 做任何判定；二次升级按 `origin IS NULL OR state_at < 本次迁移时间` 重跑回填（幂等）。
- 数据层回滚不做（不删列、不重建表）；保留 P3 前与 P4 前两个备份直到 P5 验收。

### 7.3 15 项测试保护矩阵

| 测试类（项数） | 依赖的现契约 | ② 的保护动作 |
