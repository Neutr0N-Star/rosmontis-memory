## 2 接口实现情况（docs/15 §3.1）

契约签名全部存在，且**额外可选关键字**用于解决「契约签名不带库句柄」的问题（不传时用 `pipeline.bind()` 的上下文，显式传参优先）：

```python
# alaya/core/item.py
@dataclass
class MemoryItem:
    id / session_id / text / origin / actor / memory_type / state /
    segments / salience / emotion / t_event / t_ingest          # §3.1 原字段
    # 实现补充（都有默认值）：role / source / author / confirmed / embedding / meta

# alaya/core/pipeline.py
def submit(item, *, project=True, cfg=None, embedder=None, llm=None) -> SubmitResult
def enrich(item_id, *, cfg=None, embedder=None, llm=None) -> EnrichResult
def transition(item_id, action, *, target="", reason="", actor="system",
               cfg=None, gate_decision=None) -> TransitionResult
# 辅助：bind / enqueue_enrich / wait_enrich / state_of / state_log / recent_log
```

结果对象字段：

- `SubmitResult`：`ok/item_id/state/tier/origin/duplicate/created/salience/emotion/enrich_queued/reason/log_id`
- `EnrichResult`：`ok/item_id/skipped/reason/added/updated/invalidated/noop/states_changed/edges_touched/source`
- `TransitionResult`：`ok/item_id/action/from_state/to_state/target/reason/gate_version/gates/log_id`

### 2.1 唯一写入点

- `INSERT INTO episode` 在 WS-A 范围内只剩 `pipeline.py`（`tests/test_items.py::TestSingleWritePoint` 做代码断言）。
- 每次 `submit()` 在同一事务里写：episode + episode_fts + 1 条 `item_state_log(action='create')`。
- 每次 `transition()` 在同一事务里写：episode 状态/兼容投影 + 1 条 `item_state_log`。
- main/被动同步写入、异步写入、主动笔记、人设升格、订正、删除都已改道。**例外见 §5.1**（dream.py / forget.py 属其它工作线）。

### 2.2 状态机（7 态，A2 §3.2）

| 动作 | 起点 | 终点 | 说明 |
|---|---|---|---|
| create（ingest） | — | note / resident / important | 沿用 `PR.default_tier` 投影；非法组合退 note |
| create（tool 有第二层 / 只有 what） | — | note / inbox | inbox 默认不可检索（C2） |
| create（system） | — | note | 系统只产候选（C7） |
| create（dream / summary） | — | dream / note | 兼容旧 tier |
| promote_resident | note / important | resident | **必须过 `PR.can_promote`**（tool_behavior 拒绝、情绪需 confirmed） |
| demote | resident / important | note | |
| mark_important / unmark_important | note / important | important / note | |
| skip（静音） | inbox/note/resident/important/dream | muted | 幂等：已 muted 直接放行 |
| archive | 任意非 archived | archived | 幂等 |
| unmute / unarchive | muted / archived | note | |
| review_note / review_archive | inbox | note / archived | 整理速记 |
| promote_persona / promote_page | note / resident / important | 状态不变 + 审计 | PR + 幅度 ≤200 字 + 频率 ≤2/会话 + 来源必须是 notebook + system 拒绝 |
| revise / revert_promotion | 任意 | 状态不变 | 只留痕 |

`tier / archived / muted` 只由 `item.projection(state)` 映射后在 pipeline 双写；`enrich()` 不改状态；运行时读取优先以 `archived/muted` 兼容列为准（旧入口直写也不会把状态机带偏）。

### 5.2 接口桥接的已知限制

- 契约 `submit/enrich/transition` 不带 cfg，`pipeline.bind(cfg, embedder, llm)` 是**进程内单绑定**。同一进程同时操作两个不同库的 `Memory` 实例时，隐式调用会用到最后一次绑定；显式传 `cfg=` 不受影响（`Memory` 内部调用都显式传参，`tools.py` 也显式传 `cfg=mem.cfg`）。多库同进程宿主需要使用时注意，或后续给契约加显式 handle。
- 异步 enrich 池是进程级（max_workers=2）；`wait_enrich()` 会关池并在下次入队时重建。同一 item 并发重复 enrich 由 `meta.enriched` 幂等标记兜底。

### 5.3 语义/行为变化

- **salience 合并成一份实现**（M3）：主动笔记从旧的 `0.55+…` 改为与被动同口径的内容证据公式（用户 +0.06、情绪 ×0.30、长文本 +0.04、状态/事实/第二层加权、无结构 −0.10）。因此新写入的主动条目显著度会比旧 demo 略低；检索行为未改（15 项基线全绿）。同字段输入经两个 origin 写入 salience 严格相等（测试断言）。
- **inbox 不可检索**（C2）只落了状态真值与 `recall_visible()` 辅助；`recall.py` 的过滤仍由 WS-B 接线（当前 recall 仍能召回 inbox 行，与 docs/11 §九 的冲突等待 CEO 拍板 C2）。
- **enrich 不再覆盖 meta_json**：主动条目四段 `what/noticed/means/next` 会保留，`meta.enriched` 合并写入（旧实现会整块覆盖，导致主动笔记在异步 enrich 后丢失四段）。
- **`notebook_promotion` 不再写入**：审计统一进 `item_state_log`。`notebook_revert(promotion_id)` 兼容新日志 id 与旧表 id；旧表不更新 `reverted`（只读）。
- **人设升格把状态留在 note**（A2 动作表：`promote_persona/page` 不迁状态，只留痕）；旧实现也不改 tier，对外行为一致。
- **`remove()` 现在走 archive 状态**：墓碑仍是删除真值；旧实现同时置 `muted=1`，新实现只置 `archived=1`（recall 的 archived 过滤已足够），15 项 `TestTombstone` 通过。
- **迁移 `state_at`**：存量回填为迁移时间，不是历史原始转移时间（A2 允许；回滚窗口用 `origin IS NULL / state_at` 重跑回填）。
- **C1（≥2 次梦复现 + ≥3 天）** 预留闸未实现（A2 要求默认关闭）；`gate` 里已有位置，启用时只需加常量与检查项。
- **fact 生命周期**：`fact.archived` 列与 `origin` 已迁移，但 fact 的衰减/归档执行仍属 WS-B 的 P4（forget 目前不扫 fact）；C3 拍板后接线。

### 5.4 无阻塞的小项

- `pipeline.transition()` 只改状态与审计；`promote_persona/page` 的实体写入在 `notebook.promote()` 完成（先过 gate，再写 persona/page，再 transition 留痕）。若 persona 写入成功而 transition 因进程崩溃失败，会出现「有人设行、无审计」的小窗口；概率极低，后续可把 side-effect 回调并入 pipeline。
