## 1 算法与复杂度

### 1.1 点火（`seed_nodes`）

三路点火，各自给 0–1 的点火强度，同名节点取最大强度并合并来源：

| 路 | 取数 | 强度 | 说明 |
|---|---|---|---|
| 向量 kNN | `fact/episode` 的 embedding，余弦排序取 top k | 余弦绝对量软映射 `clamp((cos-0.20)/0.55, 0.05, 1)` | 不做排名归一；余弦 0.2 以下就是弱点火 |
| FTS5 关键词 | `fact_fts/episode_fts`，`ORDER BY rank` | `max(0.30, 0.92-0.02·rank)` | 中文无 jieba 时用字符二元组，FTS 侧同构 |
| 实体命中 | query token 命中 `entity`（精确 + 子串），再取该实体 **1 跳**邻域 fact/episode | 实体 0.55+0.35·salience；1 跳 fact 0.52 / episode 0.45 | 冷启动没有结构边时，这一路仍直接产出候选 |

实现细节：

- `recall` 已经把 dense/sparse 算过一遍，`_field_route` 通过 `routes={"vec": dense_ids, "fts": sparse_ids}` 复用，不重复扫向量表；单独调用 `seed_nodes()` 时才自行取数。
- 向量路任何异常（无 embedder、服务降级、维度不符、embedding 为空）只让这一路变空，FTS+实体照常点火；`tests/test_field.py::test_vector_route_unavailable` 覆盖。
- 种子上限 `MAX_SEEDS=96`，防止一次点火把候选池撑爆。
- 节点键统一为 `"kind:id"`（`fact:` / `episode:` / `entity:`），`Seed` 同时暴露 `kind/ref_id`。

### 1.2 扩散（`propagate`）

稳定化的离散热传导，逐轮做：

```
φ' = (1-α)·φ + α·(D⁻¹A)·φ          α = decay ∈ [0,1]，默认 0.45
```

- 这是 `docs/15 §1.1` 的 `φ ← φ + min(α,1)·D·L_norm·φ` 的**稳定离散形式**：取 `L_norm = D⁻¹A - I`，结果恒为「自身与邻居加权均值」的凸组合，因此**有界、不发散**。取 `D⁻¹A`（行归一）而不是对称归一，是为了保证每行权重和为 1，避免高密度节点把激活放大。
- 稀疏表示：`dict[node, dict[neighbor, weight]]`，每轮只遍历边表，复杂度 **O(E × iter)**；`iterations` 硬上限 `MAX_HOPS=3`，深度来自 `REFLEX_DEPTH[depth]["hops"]`（instant=0 / context=1 / habit=2 / deep=3）。
- 邻接按**前沿增量加载**，不建全库邻接：
  - 结构边（`structural`）：同一条 `hyperedge` 内成员两两相连，权重 `0.85·min(w_i,w_j)/(n-1)`；一条超边超过 12 个成员时，只把成员接到权重最高的 6 个枢纽上，避免 O(n²)。
  - 共现边（`cooccur`）：`fact ↔ 主语/客体 entity`（0.55/0.48）、`episode ↔ 其 fact 的 entity`（0.35）。
  - 溯源边（`provenance`）：`fact ↔ source_episode`（0.50）。
  - `_structual_edges` 与 `_fact_edges` 各合并成 1 条 SQL（三类前沿用 OR），一次扩散只有 2 条邻接查询。
- 保护：单步边预算 `MAX_EDGES_PER_STEP=4000`、节点上限 `MAX_PHI_NODES=4000`、`MIN_PHI=1e-3` 剪枝；迭代本身是有限轮次，环路不会死循环。
- 返回 `PhiMap`（`dict` 子类），除 `{node: φ}` 外附 `iterations / edge_types / dist / seed_count`；`recall` 直接把它们写进 `plan_json`，不再二次查库。`dist` 记录节点到种子的跳数，用于把扩散结果折算成 `graph_prox=1/(1+跳数)`。

复杂度汇总：

| 操作 | 复杂度 | 上界 |
|---|---|---|
| `seed_nodes` | O(向量扫描 + FTS + 实体邻域) | 向量/FTS 各 LIMIT；实体 LIMIT 16，1 跳 LIMIT 24 |
| `propagate` | O(E × iter) | iter≤3，E≤4000 边/步，节点≤4000 |
| `activation` | O(min(32, 痕迹数)) 一次查库 | 每候选一次；批量路径用纯函数 `activation_from_parts` 不查库 |
| `field_metrics` | O(nodes) 的 COUNT/GROUP BY | 度分布 LIMIT 20000 |

### 1.3 激活（`activation`）

```
A_i(t) = ln( Σ_j (t - t_j)^-0.5 ) + B_i ,   B_i = salience × 2
```

库里没有逐次访问时间线，用已有字段重建痕迹（`activation_from_parts`，纯函数）：

- 编码时刻（episode 的 `t_event` / fact 的 `t_valid_from`）恒算 1 条痕迹；
- `last_access` 按 `min(access_count, 16)` 次重复计入（次数越多，痕迹越密）；
- 无 `last_access` 时退化为只有编码痕迹；`dt` 下限 1 秒，避免除零/未来时间。

`A` 是对数量纲（1 秒前约 0，1 天前约 −5.7）。打分不直接用 A，而用 `activation_odds(A)`：

```
odds(A) = σ(A - A0),  A0 = -0.25·ln(86400) ≈ -2.84
```

`A0` 取「刚发生」与「1 天前」两个激活值的对数时间中点，于是单条 1 天前的痕迹约 0.5、1 小时前约 0.8、1 个月前趋近 0。这保留了 ACT-R 的单调性与时间衰减，又落在 (0,1)，不会把分数压死。

### 1.4 三空间衰减（`space_of` + `SPACE_DECAY`）

`memory_field.SPACE_DECAY` 原样保留：`identity 0.1 / knowledge 1.0 / operational 3.0`。归属按 `docs/15 §1.1`：

| kind / 条件 | 空间 |
|---|---|
| `persona`、`memory_type=identity`、`source=seed` | identity |
| `fact / state / entity / theme / page` | knowledge |
| `tier=resident` 的 episode | identity（一直知道的事，不按情节衰减） |
| `source=summary/self_reflection` 或 `memory_type∈{principle,preference,lesson}` 的 episode | knowledge |
| 其余对话 episode（含 `tool_behavior`） | operational |

两处真实调用：

1. **打分**：`final = raw × (1 + α·odds(A)·space_weight)`，`space_weight = SPACE_DECAY[space]/1.0`（identity 0.1 / knowledge 1.0 / operational 3.0），`α=w.access_boost=0.08` 不变。含义：人格几乎不靠「最近被想起」排序，操作状态最吃新近性；公式骨架仍是 `docs/03 §4.3` 的 `raw × (1 + α·x)`，只换了 `x` 的构造。
2. **遗忘**：`retention()` 里 `Δt_eff = Δt × SPACE_DECAY[space]`，即 identity 的半衰期 ×10、operational ÷3。默认 `space="knowledge"`，`audit.py` 不传参的旧调用行为与改造前完全一致。

## 2 接线点

### 2.1 `score.py`

- `Candidate` 增加 `space: str = ""`、`activation: float | None = None`。
- `rank_and_densify()` 在打分前统一补齐：`space = classify_space(kind, tier, meta.source, memory_type)`，`activation = activation_from_parts(t_ref, last_recall, access_count, salience, now)`，每条只算一次。
- `score_one()` 把 `1 + α·log(1+access_count)` 换成 `1 + α·odds(A)·space_weight`，boost 夹在 `[1.0, 1.5]`，最终分仍 `clamp(0, 1.5)`。
- 分项 `rel/time/salience/graph/emotion/polarity/scope` 与权重原样保留。

### 2.2 `recall.py`

- 新增 `_field_route()`：`seed_nodes(routes=...)` → `propagate()`，返回 `fact/episode` 节点键列表，参与 RRF 融合，与 dense/sparse/graph 并列。
- `plan_json` 新增：`field_enabled / seeds（数量）/ seed_top / iterations / edge_types / phi_top`。`ALAYA_FIELD=0` 时 `field_enabled=false` 且其余为零，回放可区分。
- 新增 `_apply_field()`：只对 `dist≥1` 的扩散节点抬 `graph_prox = 相对激活/(1+跳数)`；种子是直接命中，不重复抬分。
- 删除旧的 `_adjacency()/_expand_by_field()`：它们做的超边邻接与扩散已由 `field.propagate` 统一实现，避免同一件事两份代码。
- 顺手修复 `_sparse()`：之前 fact/episode 两张 FTS 共用 `t.source!='dream'`，而 `fact` 表没有 `source` 列，fact 那一路一直在 `except` 里静默失败。改为按表给过滤条件（fact 用 `status!='invalidated'`，episode 用 `archived=0 AND source!='dream'`）。这是本报告里唯一影响「场之外」的检索行为改动，方向是**多一路候选**；20 条固定查询回放中无一条命中变差（见 §3.3）。
- `_pack()` 一字未改。

### 2.3 `forget.py`

- `retention(cfg, t_ref, access_count, salience, now, *, space="knowledge")`：`Δt × decay_factor(space)`。
- `run_decay_only()` 与 `run()` 的 episode 查询补 `tier/source/memory_type`，逐行算空间后传入。
- 折叠/归档阈值（`forget_archive_r=0.08`、`forget_protect_salience>=0.8`、`pinned`）不变。

### 2.4 `memory_field.py`

- 保留 `SPACE_DECAY / ACT_R_DECAY / BASE_ACTIVATION / DEFAULT_GAMMA / MAX_HOPS`。
- 新增 `classify_space / space_weight / activation_value / activation_odds / laplacian_step`；`space_of`、`decay_factor`、`Activation`、`spread`、`critical_nodes`、`normalize_scores` 保留兼容签名。
- `laplacian_step` 是纯函数，单测可直接喂 `{node: {neighbor: w}}` 验证有界性。

## 3 开 / 关场对比数据

采集方式：真库只读副本（`demo.db` 9 条 episode / `alaya.db` 182 条），每个查询用一份全新副本 + 一次暖场检索，避免 `access_count/cooldown` 在查询间串扰；每档每查询跑 3 次取中位。开关为环境变量 `ALAYA_FIELD=1/0`。

固定查询集 20 条：`demo` 8 条（名字/住址/工作/团子/动物/旧偏好/心情/换工作）；`alaya.db` 会话 `mq1` 5 条、`mq2` 3 条、`mq3` 2 条、`main` 2 条。命中 = top-10 选中项里出现该查询的任一金标证据（fact 或 episode）。`alaya.db` 的向量是 bge-m3，本机无 embedding 服务，因此以「向量路不可用」降级模式跑（`NoVec`），只靠 FTS + 实体 + 结构扩散——这同时验证了 §4 的降级要求。

### 3.2 延迟解释（D5 口径）

- 场本身（点火 + 扩散，不含候选加载）在真库上的中位开销：**0.19–0.32 ms/次**（`demo` 0.32 ms、`mq1` 0.23 ms、`mq3` 0.19 ms）；`recall` 总开销增加约 0.3–0.5 ms/次（含扩散候选的 `_load_candidate` 与 plan 记录）。
- 9 条 / 182 条这种微型库的基线检索只有 1 ms 量级，固定开销占比因此超过 20%；这是分母效应，不是场随规模变慢。
- 在 **19,809 条 episode** 的规模副本（真库只读复制扩容，dense 扫描已顶到 20000 上限，等价于 10 万级单次扫描的最坏情况）上复测：

| 规模副本 | 场关 p50 / p95 / max | 场开 p50 / p95 / max | p50 增量 |
|---|---|---|---|
| 19,809 episode（94 MB） | 388.7 / 427.1 / 434.1 ms | 385.1 / 420.3 / 444.9 ms | **−0.9%**（在噪声内） |

  该副本的绝对延迟由既有 dense 全表扫描（80 MB embedding BLOB）主导，不是场引入的；场在该规模下没有可测的延迟增量。**建议 D5 的「<20%」在 1 万条以上、缓存已热的库上判定**；微型库上应按绝对开销（<0.5 ms）判定。

- 最慢的一次检索：真库 **3.6 ms**（demo「我以前喜欢猫吗？」，2 轮扩散）；在 19,809 条副本上最慢 444.9 ms（场开）/434.1 ms（场关），同样是 dense 扫描主导。

## 5 风险与需要其他线配合的事

1. **D5 的延迟判定口径**：微型库上固定开销占比 >20%，2 万条以上无可测增量。需 WS-D 在基准集上按目标规模判定，并把「场固定开销 <0.5 ms/次」作为微型库口径。
2. **ACT-R 痕迹是近似**：schema 目前只有 `access_count + last_access`，没有逐次访问表。当前把 `last_access` 按次数重复计入；若 WS-A 后续补访问痕迹（例如 enrichment 时写 access trace），`activation_from_parts` 可直接换数据源，函数签名不变。**这是跨线需求，不在本线改 schema。**
3. **实体点火的可扩展性**：`instr(query, norm_name)` 会按会话扫 `entity` 表。当前库（34–50 实体）无影响；10 万实体级需要 entity 的 FTS 或 token→entity 倒排，属 WS-A enrich 的地盘。建议 WS-A 在实体 upsert 时同步维护一个轻量倒排。
4. **语义边未在扩散内重建**：`docs/15 §1.1` 的「向量 kNN k=8、cos>0.72」语义边，本实现落在**点火路**（query→节点）而不是「节点→节点」的逐点 kNN。理由：逐点 kNN 需要为每个扩散节点扫全库向量或维护近似索引，与「不落库、查询时按需构建」冲突，成本也超出 120 ms 预算；查询侧语义入口已由 dense 点火覆盖。若后续要补，建议 WS-D 用离线 kNN 图评估收益后再定。
5. **空间归属是启发式映射**：`space_of` 按 `tier/source/memory_type` 推，`resident→identity`、`summary/principle/preference→knowledge`、其余对话 `→operational`。其中 operational 的 3× 衰减会让对话情节的归档时间从约 53 天缩到约 18 天（salience=0.5、零访问时 R<0.08 的时点），**请 WS-A/产品确认这是否符合「会话进度烧得快」的产品口径**；如果过激，把 `_salience` 或 space 映射调一格即可，不动公式。
6. **`field` 的公共入口需要上下文**：契约签名没有 `cfg/embedder`，本实现用 `bind(cfg, embedder)` 的线程默认值补齐，也接受显式 `cfg=`。WS-C 若直接调 `field_metrics`/`seed_nodes`，需先 `bind`（或改为走 `recall`）。未 bind 时安全返回空，不会抛错。
7. **fact 侧 FTS 修复的连带变化**：`_sparse` 现在真的会召回 fact 关键词命中，候选池变大；20 条回放里只带来改优，无预算/拒答回归。其它依赖「fact FTS 永远为空」的旧代码（若有）需知悉。
8. **数据量与内存**：邻接按前沿增量加载 + 单步 4000 边上限；极端稠密会话（单条超边 30 成员 ×200 边）会被截断，`field_metrics.edges` 可观测到截断前的结构规模。
