## 2. 公共 API v1 清单

```python
import alaya
h = alaya.open("alaya.db", {
    "embed_provider": "hash",       # 任意 Config 字段可覆盖
    "llm_hot": "rule",
    "llm_callable": my_llm,         # 或 "llm"；Handle 级选项
    "system_prompt": "...",         # 可选
    "auto_tick": False,             # 默认 False：节拍交给调度器
    "memory_budget": 1400,          # 可选
    "max_tool_rounds": 3,           # 可选
    "observe_window": 300.0,        # observe 幂等窗口（秒）
})
```

| 方法 | 返回 | 纪律 |
|---|---|---|
| `alaya.open(db_path, config=None) -> Handle` | Handle | `db_path` 空 / config 非 dict / 打不开时抛 `AlayaError` |
| `wake(space, conversation)` | `{ok, space, conversation, session_id, persona_text, persona_chars, persona_budget, persona_items, resident_text, resident_tokens, inbox, degraded}` | 幂等（种子 `INSERT OR IGNORE`） |
| `context(space, conversation, query, budget=None)` | `{ok, ..., system_prefix, memory_text, tokens, memory_tokens, persona_tokens, abstained, budget, parts, latency_ms, as_of, pure}` | **纯函数**：不写库（含 `retrieval_log`）；`memory_tokens ≤ budget`（硬闸整行裁剪） |
| `turn(space, conversation, text, *, history=None, extra_system=None)` | `TurnResult.to_dict()` + `ok/space/conversation/session_id` | 空文本抛 `invalid_argument`；模型失联抛 `llm_unavailable`（retryable） |
| `observe(space, conversation, user_text, assistant_text)` | `{ok, queued, idempotent, written, user/assistant: ingest 结果}` | 同文本窗口内幂等；不生成回答 |
| `settle(space, conversation)` | `{ok, job_id, queued, deduplicated}` | **立即返回**；结算/整理/做梦在后台线程；同 session 进行中任务去重 |
| `close()` | `None` | 可重复调用；等后台任务与 enrich 收尾 |
| `job(job_id)` / `wait(job_id, timeout=60)` | job dict | `wait` 是可选的同步查看法，不是契约要求 |
| `tool(space, conversation, name, args)` | 工具六键/recall 结果 | 宿主自管循环时直接用 |
| `item_state(item_id)` / `transition(item_id, action, *, target, reason, actor)` | state / 六键 | 运维入口 |

错误：`AlayaError`（别名 `ApiError`），字段 `.code/.message/.retryable`，`.as_dict()` 给出
`{"ok": false, "data": null, "error": {"code","message","retryable"}}`（docs/15 §3.4）。
公共 API 版本：`alaya.api.__version__ == "1"`；包版本仍为 `__version__ = "1.0.0"`。

### v1 的 space / conversation 映射（重要）

底层 `Memory` 目前只有一层 `session_id`（WS-A 的两层隔离/schema 刚落地但 Memory 门面未拆）。
v1 实现取 **`session_id = space`**：同一 memory space 的不同 conversation 共享记忆
（对应「换会话不失忆」的产品要求）；`conversation` 原样带回并参与 `observe` 幂等键。
conversation 级隔离依赖 WS-A 把 `space_id/conversation_id` 贯穿到存储层，见 §5 依赖点 D4。

## 3. 四钩子契约（宿主自管循环）

| 钩子 | 调什么 | 返回/纪律 |
|---|---|---|
| `session_start` | `wake(space, conversation)` | 人格文本 + 常驻文本 + inbox + degraded；幂等 |
| `pre_prompt` | `context(space, conversation, query, budget)` | `system_prefix / memory_text / tokens / abstained`；纯函数、绝不超预算；拿不到返回空而不是硬凑 |
| `post_turn` | `observe(space, conversation, user_text, assistant_text)` | 立即返回 `queued`；同一文本窗口内不产生第二条记忆 |
| `session_end` | `settle(space, conversation)` | 立即返回 `job_id`；后台跑峰终/整理/做梦，不挂住宿主退出流程 |

`examples/hooks_demo.py` 按上表顺序跑通，并额外验证：
- `pre_prompt` 前后 `episode / retrieval_log` 计数不变；
- 工具写下的笔记在下一轮 `pre_prompt` 被检索到（`memory 51/400 token`）；
- `settle` 受理耗时 ~0.4ms，`wait` 后状态 `done`。
- 宿主 own-loop 的 `post_turn` 用 `observe` 演示，第二次同文本 `idempotent=True`。

## 4. 工具契约与底层透传

### 4.1 写类工具统一六键

```json
{"ok": true, "id": "ep_...", "state": "note", "from": "new", "to": "note", "reason": "..."}
```

- `state` 取值：`inbox | note | resident | important | archived | muted | dream`（docs/15 §3.1）。
- 语义：工具只提交 item，**状态由 gate 决定**；被拒绝时 `ok=false`、`state` 停在 `from`、`reason` 原样给模型。
- `alaya_remember`：只有 `what` → `inbox`；有 `noticed/means/next` → `note`（WS-A `gate.initial_state`）。
- `alaya_promote`：走 `notebook.promote` → `gate.decide`；单会话第 3 次返回
  `ok=false, reason="单次会话最多改 2 次人设（已用 2 次）…"`；成功时 `state` 等于 gate 的 `to`。
- `alaya_revise`：仍走 notebook correction；返回新 id 与 `state`。
- `alaya_skip`：episode 走 `pipeline.transition("skip")`（`state=muted`，不删除）；fact 没有
  状态机入口，落 `status='invalidated' + archived=1 + t_invalid=now`（**t_valid_to 保持 NULL**，
  表示「世界时间仍有效，只是不再浮现」）。这样 `item_state()` 能把「静音(muted)」与
  「归档(archived，t_valid_to 已结束)」区分开；召回各路径都过滤 `invalidated`，跳过即不再命中。
- `alaya_recall` 是读工具，保持 `{ok, found, prompt, count}` 结构。
- `dispatch` 兜底异常返回 `{"ok": false, "reason": "执行出错：<类型>: <消息>"}`，只给类名的问题已修。

### 4.2 工具的模型侧协议（OpenAI 兼容）

- `TOOLS` 仍是 5 个 OpenAI function schema。
- harness 工具循环：assistant 消息写 `tool_calls[{id,type,function{name,arguments}}]`；
  tool 消息写 `{role:"tool", tool_call_id, name, content}`；缺失的 `id` 用
  `call_<sha1(name,args,index)[:16]>` 补。
- `llm_callable` 返回值新增可选 `usage` / `finish_reason`，缺省不崩；`TurnResult` 暴露两者，
  多轮 usage 数值累加。

### 4.3 根因修复：`service/app.py` 的 `llm_call`

旧链路：`messages → 压成 system+对话文本 → LLM.chat()`，模型拿不到 `tools`，`tool_calls` 恒 `[]`，
五个工具在真实服务里是死代码。新链路：

```
Harness._run_loop
  └─ llm_callable = make_llm_callable(mem.llm_hot, clean=_clean_reply)
       ├─ chat_with_tools(llm, messages, tools)     # OpenAI 兼容 / Ollama，带 tools 字段
       │    ├─ parse_openai_chat_response()         # choices[0].message.tool_calls → 归一并补 id
       │    └─ parse_ollama_chat_response()         # message.tool_calls + eval counts → usage
       └─ 失败 → 纯文本通道（tool 轮压成「（工具结果）…」），tool_calls=[]，不抛
```

`usage`（prompt/completion/total）与 `finish_reason` 原样带回；无密钥 / 无网络 / 上游 4xx /
坏 JSON 一律安静降级。**证据**：`tests/test_api.py::TestOpenAICompatiblePassthrough`
用假 `urlopen` 喂 OpenAI 兼容响应，断言 ①首次请求带 `tools`+`tool_choice=auto`；
②`call_abc` 被 dispatcher 执行并落库 `source='notebook'`；③第二次请求
`assistant.tool_calls[0].id == tool.tool_call_id == "call_abc"`；④usage 累加、`finish_reason=stop`。

## 7. 风险与未做

| # | 风险 | 影响 | 建议 |
|---|---|---|---|
| R1 | 本机未安装 FastAPI，`service/app.py` 只做了 `py_compile` + 共享 helper 单测 | 两个新运维接口与 `llm_call` 的 HTTP 层未经真实进程验证 | 装 extras 后启动 `python run.py serve` 冒烟 `/docs`、`/v1/items/{id}/state`、`/v1/items/{id}/transition` |
| R2 | `settle` 任务是内存线程，进程崩溃/退出会丢 | 结算/整理可能不执行 | A3-M0 的 jobs 表 + 调度器；宿主侧可在 close 前 `wait(job_id)` |
| R3 | `context` 纯函数依赖「recall 唯一写点 `_log`」这一事实 | 若 WS-B 在 recall 新加写库点，纯函数契约会被破坏 | `tests/test_api.py::test_context_is_pure_and_within_budget` 会立刻变红，守住 |
| R4 | 纯函数用「本线程静音 `core.recall._log`」实现（全局函数套按线程标记） | 若其它库缓存了 `_log` 原函数会绕过；但审计日志只会少写不会多写 | 长期应由 WS-B 给 recall 加 `log=False` 形参，本层再切过去 |
| R5 | `observe` 幂等是进程内窗口缓存 | 多进程/重启后同文本可能重复落库 | 服务端单 worker 可接受；多进程需幂等键落库（A3-M0） |
| R6 | fact skip 用 `invalidated + t_valid_to=NULL` 表达 | 状态机外挂的兼容写法 | 等 D3 的 fact 状态机 |
| R7 | `_promote` 对「gate 通过但 notebook 写人格失败」无补偿 | 极端情况下状态与人格不同步 | WS-A 把 notebook 也收口到 pipeline 后该窗口消失 |
| R8 | 工具返回 `state` 对 promote_persona 是 `note`（gate 规定升人格不改 item 状态） | 调用方若把 `state` 当「已进人格」会误读 | 以 `ok` 判断动作成功、`state` 判断 item 生命周期；报告即口径 |

未做：MCP 适配器、Claude Code hooks 脚本、流式/异步 `turn_async`、`/metrics`、持久 jobs、
真实 OpenAI/Ollama 联网冒烟（本轮明确不联网）。
