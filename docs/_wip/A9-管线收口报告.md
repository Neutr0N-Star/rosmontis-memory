## 3 实现细节

### 3.1 dream 产物（`dream.py`）

```python
dream_item = IT.MemoryItem(
    id=dream_id, session_id=session_id, text=body,
    origin=IT.ORIGIN_DREAM, actor=IT.ACTOR_MODEL,   # episode.author 兼容投影 = self
    memory_type="fact", role="dream", source="dream",
    salience=0.4, emotion=0.0, t_event=now, t_ingest=now,
    embedding=embs, meta={"evidence": [...], "abstracts": [...], "themes": [...]},
)
sub = TR.submit(dream_item, project=False, cfg=cfg, embedder=embedder, llm=llm)
```

- 状态由 `gate.initial_state(origin='dream')` 判为 `dream`，`tier/archived/muted` 由 `item.projection()` 双写。
- `dream_log` 仍在 episode 落库之后单独事务写；`submit` 返回 `duplicate` 时不重复写 episode/FTS/日志。
- `project=False`：梦是加工产物，不再对它二次抽取。

### 3.2 forget 折叠摘要（`forget.py`）

```python
summary_item = IT.MemoryItem(
    id="ep_fold_" + digest(edge, int(now)), session_id=members[0]["session_id"],
    text=text, origin=IT.ORIGIN_SUMMARY, actor=IT.ACTOR_SYSTEM,
    memory_type="fact", role="summary", source="summary",
    salience=0.55, emotion=0.0, t_event=members[-1]["t_event"], t_ingest=now,
    meta={"is_summary": True},
)
sub = TR.submit(summary_item, project=False, ...)
```

- 折叠分组、成员读取在 `DB.reader` 里完成；摘要落库后，再用一个小事务写回 `folded_into` 与 `hyperedge_member(weight=1.2)`。
- 摘要保存 `role='summary'`、`source='summary'`，旧查询（`dream.candidates_for_promotion` 等按 source 过滤的地方）语义不变。
- 重复跑 `forget` 时，已折叠/已归档的条目不会再进入 cold 集合，因此不会产生第二条摘要。

### 3.3 forget 归档（两处 → 状态机）

`run_decay_only` 与 `run()` 的归档循环都改成：

```python
tr = TR.transition(item_id, "archive", reason="...", actor=IT.ACTOR_SYSTEM, cfg=cfg)
if tr.ok and tr.from_state != tr.to_state: n += 1
```

- 每次归档 = 1 条事务（episode.state/投影 + `item_state_log`）。
- 单条失败只记 `rep.errors` / log.warning，不中断整轮遗忘；重复执行幂等（已 archived 直接放行）。

### 3.4 enrich 后重算 salience（评审 B4）

`write.enrich` 现在的落库事务：

```
[同一事务] memory_type 修正 → _canonical_salience(...) 计算 → _project_extraction(...)
           → UPDATE episode SET salience=? → 合并 meta(enriched)
```

`_canonical_salience` 从库里的文本/情绪/actor/segments + 本次抽取证据，调用**同一个** `write.salience_of`。
注意顺序：salience 在 `_project_extraction` **之前**算，因为 `_resolve_fact` 会原地把 predicate 归一化，而同步 ingest 的 salience 是按归一化前谓词算的；顺序一致才能严格相等。

> 口径说明：评审 B4 写的是 `score.salience_of`；当前唯一实现位于 `write.salience_of`（`score.py` 属语义场线文件，本轮独占清单不含它，且 A5 起所有入口都引用 write 这一份）。如果后续 WS-B 把函数搬进 `score.py`，只需保留一个 re-export，enrich 与 submit 都会自动跟到同一份实现。

## 5 行为变化与风险

1. **事务粒度变细**：dream_log、折叠成员回写、逐条归档各自成事务，不再与 episode 写入同一大事务。好处是遵守「单一写入点 + 状态/日志同事务」；代价是极端崩溃时可能出现「摘要已建、成员 folded_into 未写」或「episode 已写、dream_log 未写」的中间态。这些中间态可重跑（submit/transition 幂等），不会产生重复 episode。
2. **dream 同秒重复**：pipeline id 为 `ep_dream_<session,int(now)>`；同秒重复调用返回 duplicate 并跳过 dream_log。正常路径由 `should_dream` 的 6h 间隔保护，实际不会触发。
3. **enrich 会改写 salience**：主动 tool 条目在 enrich 后 salience 会按「文本+segments+抽取证据」重算（可能高于/低于 submit 时），这是 M3 统一口径的预期结果；同步 ingest 不经过 enrich，故基线不变（15/15 验证）。
4. **全仓仍有非 episode 的旁路写**（不在本任务范围）：`tools.py` 降级分支会直接写 `muted/state`（无 pipeline 时兜底）、`dream.py` 仍直接写 `emotion`（脱敏，非生命周期字段）。前者仅在 pipeline 不可用时触发，后者是内容字段。
5. **契约桥接限制沿用 A5**：`pipeline.bind` 是进程内单绑定；多库同进程需显式传 `cfg=`（Memory/tools 已显式传）。
6. **归档性能**：`run_decay_only` / `run()` 的归档改成逐条 `transition`（每条一次读 + 一次事务），冷条目上千时比旧的单事务 UPDATE 慢。当前真库规模（182 episode）无感；后续如需批量，可在 pipeline 增加 `transition_many`（保持单条日志语义）。
7. **未做**：`recall.py` 的 C2「inbox 不可检索」过滤仍属语义场线；fact 生命周期（M4b）仍属 W5；`docs/14 §2.3` 的文字更新由文档 owner 在合入时改。
