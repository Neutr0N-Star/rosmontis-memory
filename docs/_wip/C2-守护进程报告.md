## 0. 结论

- `job` 表已落地（`db.py` 幂等 `CREATE TABLE IF NOT EXISTS`，不改 `user_version`），`core/jobs.py` 提供

## 2. jobs 表与 `core/jobs.py`

`db.py` 幂等补表（字段与 docs/15 §3.5 一致）：id / kind / target / status / attempts / max_attempts /
next_run / lease_owner / leased_until / last_error / created_at / updated_at + `idx_job_due`、`idx_job_lease`。
老库打开时 `DB.init_db` 即补表，不改 `PRAGMA user_version`。

`core/jobs.py`：

| 函数 | 语义 |
|---|---|
| `enqueue(cfg, kind, target, next_run=None, *, bucket=None)` | 确定性 id `kind+target+时间窗`；`INSERT OR IGNORE`，重复投递 `created=False` |
| `claim_due(cfg, limit, owner=, now=, lease_seconds=300)` | 事务内抢占 pending/failed 且到点的 job：`status=running`、`attempts+1`、写 lease；单写者 |
| `claim_job(cfg, job_id, owner=, now=)` | 指定 job 抢占（HTTP `/v1/settle` 的立即执行线程用）；与 daemon 跨进程条件更新，只有一方成功 |
| `finish / fail` | done 清 lease；失败按 `min(2^attempts, 300)s` 退避，超过 `max_attempts` → `dead`，`last_error` 保留 |
| `requeue_stale(cfg, now=)` | 收回 `status=running AND leased_until < now`：未超限回 pending，超限进 dead |
| `execute_job(mem, job, now=)` | kind → Memory 方法映射：`settle→close_session`、`review→notebook_review`、`dream→dream`、`forget→forget("*")`、`enrich→pipeline.enrich`、`tick`、`backfill`（占位） |
| `counts / summary / list_jobs / due_count` | 供 `GET /v1/jobs` 与日志 |
| `idem_begin / idem_store / idem_release` | 幂等键（见 §4）；独立表 `http_idempotency`，24h TTL，状态 running/done |

job id 示例（确定性）：`job_495eba66afcf420f55d17a48`（kind=forget, target=\*, 窗口=6h）。

## 3. daemon（`alaya daemon`）

```text
每拍：
  ① jobs.requeue_stale(now)                 # 收回过期租约
  ② 发现（默认开启）
     - Memory.idle_sessions(idle_timeout, max_age=ALAYA_SESSION_MAX_AGE 24h)
         → enqueue settle，bucket=last_active（同一空闲期只结算一次）
     - 最近 session（last_active 24h 内）
         - mem.inbox(sid).should_review → enqueue review（窗口 = review_interval_hours）
         - DM.should_dream(cfg, sid, now) → enqueue dream（窗口 = dream_interval_hours）
     - cfg.auto_forget → enqueue forget("*")（窗口 = ALAYA_FORGET_INTERVAL，默认 6h）
  ③ jobs.claim_due(limit, owner) → 逐个 execute_job → finish/fail
  ④ 一行一任务日志；dream 结果额外写 meta `dream_check:<sid>:<day>`（D4b）
```

- 默认心跳 60s；`--once` 只跑一拍并打印 JSON 摘要（供验收/测试）。
- `--interval / --idle-timeout / --limit / --owner` 可配；`ALAYA_IDLE_TIMEOUT` 默认 1800s。
- 退出：注册 SIGINT/SIGTERM（Windows 额外 SIGBREAK/SIGHUP 若存在）→ 置 stop 事件；当前任务执行完退出，
  打印 `[daemon] signal=...，当前任务执行完后退出`、`[daemon] stopped`，返回 0；
  `run_daemon(stop_event=...)` 可注入停止，测试不真等 30 分钟。
- 空闲判定 `Memory.idle_sessions()` 用 `last_active`（写入路径持续更新）；`ALAYA_SETTLE_MAX_AGE`（默认 86400s）
  防止把历史会话全部翻出重结算。`Config.idle_timeout_s` **未加**（config.py 不在本轮独占文件里），故走 env；
  推荐后续在 `Config` 落一个字段并把 env 读取收口。

## 4. HTTP 接口与幂等键

### 4.1 `POST /v1/settle`

请求：`{"session_id": "u1"}`（空 body/query 默认 `default`，也支持 `?session_id=`）；返回立即：
`{"ok": true, "data": {"job_id": "job_...", "session_id": "u1", "status": "pending", "queued": true}}`。
后台线程 `jobs.claim_job` → `execute_job(settle)` → `finish/fail`；线程登记在 lifespan join 表，
SIGTERM/关停时最多各等 5s。`/v1/session/sleep`、`/v1/turn` 行为不变。

### 4.2 `GET /v1/jobs?status=&limit=`

返回 `{"ok":true,"data":{"summary":{pending,running,done,failed,dead,total,due},"jobs":[...]}}`。

### 4.3 `Idempotency-Key`（`/v1/episodes`、`/v1/turn`；`/v1/settle` 同样支持）

- 表 `http_idempotency`（`core/jobs.py` 建）：`id`（scope+key 哈希）/`scope`/`key`/`status`/`status_code`/`response`/
  `created_at`/`updated_at`/`expires_at`，`UNIQUE(scope,key)`；TTL 24h（`ALAYA_IDEMPOTENCY_TTL` 可覆）。
- 同键第一次执行后存完整响应体；后续请求直接回放（响应头 `X-Idempotent-Replay: 1`），**不重复写记忆**。
- 同键请求处理中返回 409 `idempotency_in_progress`（retryable）；key 非 1–200 字符返回 400；
  执行异常会释放占位，允许客户端重试。
- scope 含端点（`POST:/v1/episodes` 等），不同端点同 key 不串。
- 传 key 两种方式：`Idempotency-Key` 头，或 body 字段 `idempotency_key`（`EpisodeIn/TurnIn/SettleIn` 均支持）；
  `/v1/settle` 同时兼容 `?session_id=` 查询参数、body `{"session_id"}`、缺省 `default`。

### 4.4 `POST /v1/observe`（宿主自管循环的回写钩子）

body：`{"session_id": "u1", "user_text": "...", "assistant_text": "..."}`；两个文本至少给一个，
空字符串忽略，都给则各写一条；`session_id` 必填（Pydantic 缺省 → 422 `invalid_argument`，空串 → 422 `missing_session`）。
实现复用 `Memory.ingest_async(role='user'|'assistant')`，立即返回
`{"ok":true,"data":{"queued":true,"episode_ids":[user_ep, assistant_ep]}}`；同样支持 `Idempotency-Key`（可选）。

兼容说明：`docs/17` §4 / README 已承诺该接口，本轮补齐；`/v1/turn`、`/v1/session/sleep` 行为不变。

## 6. 验证记录（全部临时库，未写 `alaya.db`）

### 6.1 daemon `--once`（真跑，输出节选）

[daemon] start owner=<host>:<pid> db=<tmp>/t.db interval=60.0s idle_timeout=60.0s once=True

### 6.2 idle 怎么验的

1. 临时库写入 `session_id=idle` 的一句话，把 `session.last_active` 改为 `now-120s`；
2. `ALAYA_IDLE_TIMEOUT=60` 跑 `python run.py daemon --once` → 产出 `kind=settle target=idle status=done`；
3. 立刻再跑一次 → `settle` job 数仍为 **1**（bucket=last_active，同一空闲期不重复结算）；
4. 单测 `test_idle_session_settles_exactly_once` 断言：discovered 含 settle、job=done、第二次 `discovered=[]`；
   `test_review_and_dream_jobs_run_and_dream_check` 断言 review/dream 到点被唤起、`dream_check:*` 落 meta；
   `test_forget_job_periodic_dedup` 断言 forget 按窗口去重。

### 6.3 幂等键是否真只写一条

```text
episodes: same_body=True status 200 200 replay_header 1 rows 1
turn:     same_body=True reply=记下了。 rows [('assistant',1),('user',1)]
```

- `/v1/episodes` 同 key 两次：响应完全一致、带 replay 头、`episode` 表仅 1 行；
- `/v1/turn` 同 key 两次：响应一致、user/assistant 各 1 行；
- 同 key 换 body 也回放首次结果（单测 `test_idempotency_episodes`）；长 key → 400（单测覆盖）。

### 6.4 SIGTERM / lifespan join 结果

环境：Windows 上 `SIGTERM` 是 `TerminateProcess`（不可捕获），uvicorn 的 graceful 路径监听的是
`SIGBREAK`（CTRL_BREAK_EVENT）；测试按平台自动选择：Windows 发 CTRL_BREAK，POSIX 发 SIGTERM。

实测（起真实 uvicorn → `/health` → `/v1/session/wake` → 发信号）：

```text
shutdown marker: {"shutdown": true, "harness_joined": true, "job_threads_joined": 0, "at": ...}
LOG: INFO:     Waiting for application shutdown.
LOG: INFO:alaya.service:shutdown: 后台任务已收尾
LOG: INFO:     Application shutdown complete.
Traceback in log: False
```

- lifespan 在关停时先 join Harness 后台线程、再 join HTTP job 线程，并写 `ALAYA_SHUTDOWN_MARKER`（测试用钩子）。
- uvicorn 在 graceful shutdown 后会 re-raise 捕获到的信号，Windows 进程退出码为 3（POSIX 为信号退出码）；
  这不是异常，标记文件与日志证明收尾已执行；测试不断言退出码。
- daemon 自身也做了真实信号测试：`python run.py daemon --interval 0.5`，发 CTRL_BREAK/SIGTERM 后
  日志出现 `[daemon] signal=...` 与 `[daemon] stopped`，无 Traceback。

## 7. 已知限制 / 风险

| R1 | Windows SIGTERM | 系统语义是 TerminateProcess，无法跑 lifespan；已用 CTRL_BREAK 等价验证，POSIX 测试走 SIGTERM | 生产 Linux/容器按 SIGTERM；Windows 用 CTRL_C/CTRL_BREAK 停服务 |
